# Agent API

## Reviewed Paste Attributes

`POST /api/clip/attributes/review` takes `_context`, target `sequence`, ordered unique `clip_ids` (1–100), frozen `donor`, `groups`, `include_animation`, `timing`, `actor` and `client`. Capture the donor at Copy: `{version:1,clip:<full snapshot>,sequence:{id,fps,width,height},context:{workspace,project,revision},media:<minimal descriptor or null>}`. Ordinary values remain available after the original donor is edited/deleted. Do not reconstruct a donor from a newer mutable clip after Review.

Groups are `motion`, `color`, `video_effects`, `audio_effects`, `mask`, `audio_gain`, `audio_controls`, `audio_fades`, `picture_transitions`. Defaults include all except mask, controls and picture transitions. Animation defaults true: replace only selected-category curves, removing selected target curves absent from the donor. False preserves target curves. `timing:"seconds"` preserves donor-local seconds; `"scale"` maps visible donor duration to each target duration. Inherited fade-window clocks follow that mapping. Source clocks, speed/reverse/hold/ramp, IDs, groups and audio linking never transfer. Offscreen anchors and live dependencies appear in warnings.

Review returns `ok`, `kind:"clip_attributes"`, exact `context`, target sequence/IDs, echoed frozen donor, canonical `settings`, `issues`, `summary` and fingerprint. Inspect ordered `summary.targets`, fields/curves, timing ratios, changed IDs and warnings. Apply with `POST /api/clip/attributes` using the exact donor, settings, target owner/selection and fingerprint. It revalidates saved state, locks, policy and resource identities, with one atomic history entry and no unrelated overlap normalization. Do not apply a refused review.

Success includes `changed`, project ID, saved context, sequence, source/target clip IDs, changed IDs, exact reviewed summary and warnings. A true no-op retains the exact revision and history. Live Matte is a same-sequence/project dependency; it does not freeze mask pixels. Stabilization requires the same captured physical-media record and analysis, with known source-signature checks. Legacy analysis has no receipt binding it to the source at analysis time; Review warns about that unverified pairing. File stat identities bind Review to Apply, not the original analysis to current source bytes. LUT/analysis file identities are stat-based; native dependency and decoded checks remain necessary. A lost or malformed acknowledgement must be reconciled through saved state/Recovery; never automatically retry or re-review.

```python
state = cr.project_state()
donor = cr.capture_clip_attributes("source-clip", "sequence", state=state)
review = cr.review_clip_attributes(donor, ["target-clip"], "sequence",
    groups=["color", "audio_fades"], include_animation=True,
    timing="seconds", context=state["context"])
# Inspect the complete review before applying it.
if review["ok"]:
    result = cr.apply_clip_attributes(review)
```

The SDK validates echoed ownership, donor, options, ordered targets and exact receipt. Omitted target context captures one saved state; explicit context requires its sequence and never triggers a replacement read.

## Reviewed Interpret Footage migration

`POST /api/media/interpret/review` takes `{_context:{workspace,project,revision},media_id,fps,include_fullmix:false,actor,client}`. `fps` is required: pass a complete positive decimal/fraction string or finite number at most 1000, or explicit `null` to restore native. Strings are bounded to 64 characters; booleans, garbage, missing rates and nonfinite numbers refuse. Rates normalize to `numerator/denominator`, including integer rates such as `24/1`; common decimal NTSC aliases retain the existing canonical rational conversion. Legacy numeric source fields remain readable.

Review is read-only and available under proposals-only policy. The response includes `ok`, exact `context`, `kind:"source_interpretation"`, selected `media_id`/`requested_media_id`, canonical `settings:{fps,include_fullmix}`, `affected_media_ids`, structured `issues`, `summary` and a 64-hex `fingerprint`. Inspect `summary.windows`, `uses`, `required_fullmix_ids`, `timing_media_ids`, warnings and cleared fields. `ok:false` is a review refusal, never permission to Apply. Unsupported source kinds may return an HTTP error.

Apply with `POST /api/media/interpret` using the review's exact `_context`, selected `media_id`, flattened canonical `fps`/`include_fullmix` and `fingerprint`, plus `actor`/`client`. Do not send arbitrary media records/ops or recapture a newer owner. The server revalidates saved state, file identities, policy and plan; changes require a fresh review. A successful reply includes the saved `project` ID, new `context`, `changed`, selected **`media` object**, affected IDs, summary/warnings and `preparation:{tasks,warnings}`. Saved-with-queue-warning is distinct from a failed edit. No-op has no new history, token or preparation. A submitted request with a lost/malformed reply must be reconciled from saved state/Recovery; never automatically replay it.

Selected ordinary subclips and discrete-channel aliases preserve their native ranges independently. Changing a physical parent requires explicit `include_fullmix:true` when legacy full-mix aliases must follow its rate; alias-only incompatible changes refuse. Timeline source In/Out, durations and processing stay authored; now-invalid uses, including locks/holds, refuse atomically. A source-wide change can alter playback on locked tracks. Known source identities survive derivative reset; available originals queue fresh preparation, while offline metadata changes retain a warning. Known VFR, still/generated and audio-only physical sources are unsupported for this operation. Declared CFR/numbered-sequence bounds do not establish full frame-cadence accuracy.

```python
review = cr.review_interpretation(media_id, "30000/1001", context=captured_context)
# Inspect review['issues'], ['summary'] and named dependents first.
if review['ok']:
    result = cr.apply_interpretation(review)
# Explicit native restore: review_interpretation(media_id, None, context=...)
# Parent group opt-in: include_fullmix=True, then inspect the new review.
```

The SDK captures once when no explicit context is given, validates returned ownership/settings, sends Apply once and never silently re-reviews. The legacy unowned `/api/media/interpret` body is no longer supported.

## Owned Subclip, Breakout and Duplicate Media migration

All three commands require one acknowledged `_context:{workspace,project,revision}`, plus `actor`/`client`. Capture selected media IDs before waiting for pending saves. Requests without ownership have no legacy fallback. `POST /api/media/subclip` takes `{media_id,in,out,name?}`; In/Out are finite exact logical seconds relative to the selected bin item. Do not add its parent offset or replace the selected ID with the parent. Names allow 1–256 trimmed Unicode characters without control characters. Recognized logical markers crop/rebase into the new window; opaque marker clocks remain with warnings. Generated Subclip and nested physical chains refuse.

`POST /api/media/breakout` takes `{media_id}` and creates 1–32 independently prepared aliases, one for each measured channel in the first physical audio stream. The internal descriptor is `audio_alias:{version:1,source_media_id,physical_media_id,channel_index}` with a zero-based index. It is a selected mono source rendered onto the stereo editing bus; `channels` retains the measured physical count. A fresh bounded probe checks that count, sample rate and selected native extent. Existing channel aliases cannot be broken out again. Arbitrary stream selection and custom decoder options are unsupported. Channel aliases may retain their own interpretation if their complete native window fits; legacy full-mix Extract Audio aliases still require compatible parent interpretation.

`POST /api/media/duplicate` takes `{media_ids:[...]}`: 1–50 distinct ordered IDs, all-or-nothing. Send IDs, never frontend-cloned media records. New records keep authored metadata but clear copied derivatives, transcript/analysis and job receipts. Physical copies and typed aliases own new preparation identities; ordinary subclips share their physical parent's preview. Offline Subclip/Duplicate saves valid metadata with warnings and no automatic preparation; Breakout requires online originals.

Success returns `{ok:true,changed:true,kind:"source_creation",mode,project,context,media_ids,media,summary,warnings,preparation:{tasks,warnings}}`. `project` is the saved project ID string. `media_ids` and complete `media` records share creation order; summary includes `kind`, `mode`, ordered `source_media_ids`, `created_media_ids`, `count` and a message. Media records describe registration, while preparation may advance later. One transaction adds the complete set; Undo includes subsequent owned preparation results without changing the original before-state. No timeline/track/clip normalization occurs. A saved command may return queue warnings; report registration separately from readiness.

Use SDK `create_subclip(media_id,in_,out,*,name=None,context=None)`, `breakout_audio(media_id,*,context=None)` and `duplicate_media(media_ids,*,context=None)`. Omitted context captures one saved owner/document; explicit context never triggers a replacement capture. Acknowledged owner, mode, IDs and records are validated, with no automatic replay or reread after an uncertain reply. Inspect saved state/Recovery before retrying a mutation. This replaces old unowned Subclip/Breakout and full-record Duplicate callbacks.

Channel preview must be verified against its own descriptor and generation even under Prefer original. Pending/stale/missing or mismatched-channel previews refuse; the raw original/full-mix fallback is forbidden for channel aliases. Ordinary export, sync and analysis select the original discrete channel before processing. AAC dual-mono preview is lossy and distinct from exact original PCM. Collection/package preserves the descriptor; relocation can require explicit owned preview preparation. Known accepted/proxy identity mismatches refuse; legacy unbound sources retain command-time stat checking rather than receiving a fabricated persisted probe acceptance. See SC01–SC06, BO01–BO08 and BC01–BC06 in the native matrix.

## Reviewed source Relink — mandatory ownership and fingerprint migration

`POST /api/media/relink/inspect` requires `{media_id,path,_context,actor?,client?}`. `_context` is one acknowledged `{workspace,project,revision}`; do not substitute the current project after inspection starts. Physical sources, ordinary subclips and typed audio aliases resolve to the same physical parent. Inspection is read-only and may be used under proposals-only policy. Invalid paths/probes/settings are HTTP failures; a readable but incompatible candidate returns `ok:false` and explicit issues without mutating the project or queueing preparation.

An inspection report includes `ok`, exact `context`, `requested_media_id`, resolved physical `media_id`, canonical server `path`, measured `info`, `affected_media_ids`, `issues`, `summary` and a 64-character lowercase hexadecimal `fingerprint`. `expectedSource` may also be supplied for compatibility diagnostics, but cannot authorize Relink on its own. Issues carry severity/code/message and scoped media/sequence/clip identifiers. Summary describes replacement native metadata, all dependent logical/native ranges and interpretation factors, all timeline uses including locks/holds, source-bound fields to clear, and warnings. `scope` is physical_source and `range_scope` is container_duration. Review that scope explicitly before applying.

`POST /api/media/relink` requires `{media_id,path,_context,fingerprint,actor?,client?}` using the unchanged requested ID, canonical path and exact context/fingerprint from that inspection. The server re-probes, rebuilds and matches the plan, checks current project/policy/file identities again, and commits one complete source-family edit with Undo. No global overlap normalization or clip/track edits occur. Missing fingerprints have no legacy fallback; stale plans require a fresh inspection. The reply includes `ok`, new `context`, saved `project` identity, `changed`, physical/requested media IDs, physical `media`, `affected_media_ids`, `summary`, `warnings` and `preparation:{tasks,warnings}`.

Every retained ordinary/reverse/ramped timeline source window and every complete dependent subclip/audio-alias window is checked, including unused bin items. Held Out is timeline duration; a held source point must exist within the replacement. Logical windows and authored interpretation targets remain; native metadata/factors refresh, and aliases retain audio-only identity with compatible parent interpretation. Stream-kind mismatches, incomplete ranges, unsupported nested subclips, generated/numbered sources and custom decoder input_opts refuse atomically. Source notes, labels, markers, authored color overrides and resource bindings remain; listed old preview/transcript/stabilization/bake fields clear and need rebuilding. This source-wide change can affect locked-track playback while preserving track and clip data.

Changed Apply saves the source records once, then attempts captured parent/audio-alias preparation. A queue/worker failure can follow a successful saved edit: read warnings and task states before retrying preparation. Completion preserves the same history transaction and never rewrites its before-state. Closing controls or losing the HTTP reply cannot withdraw an already committed command; inspect saved state and Recovery instead of replaying Apply. Reinspection of the unchanged accepted file is a real no-op with unchanged context/history/token and no preparation work. An unaccepted same-path file is an explicit new acceptance, even if its displayed metadata looks the same.

File identity uses normalized path, size, nanosecond mtime and inode stat metadata plus the probe/plan fingerprint, not a full source-content hash. Byte changes preserving every checked stat field remain outside this guarantee. Range checks use measured container duration rather than a complete packet/frame scan; VFR, delayed audio and absent stream tails require decoded-media acceptance. Paths are at most 4096 characters. Probe stdout/stderr is bounded to four MiB each with a monitored 60-second timeout; native/file blocking and polling overshoot are separate. Metadata admission limits include 32 MiB, 500,000 nodes/depth 32, 10,000 library entries, 1,000 sequences, 100,000 clips and 8,192 speed-ramp points per clip. These bounds are not native throughput qualification.

Relink's `source_relink_basis` is an internal machine-local path/stat acceptance record. Its serialized stat integers are canonical decimal strings, preserving nanosecond time and large inode values through JavaScript JSON; clients must retain them without numeric coercion. Export preflight reports `source_changed_after_relink` for a known mismatch. Verified Collect and Save As copies rebase that identity across the physical source family only after source/copy verification; a ready collection can apply from its checked copies even when the original is now offline. Clients must not manually clear or rebase this field to bypass refusal. Portable packages verify originals and transferred resource hashes, explicitly omit local acceptance records, and reject packages that reintroduce them. Import establishes checked transfer provenance rather than new source probing. Collection preserves a verified parent's proxy association where valid; an alias's own preview may become stale on path relocation and needs explicit Prepare after the prior job completes or is canceled.

SDK migration: `inspect_relink(media_id,path,*,context=None)` captures one saved owner when context is omitted and validates the returned owner/target. `apply_relink(review)` uses its canonical path, requested target and fingerprint directly; it does not read another current project or silently inspect again. `relink(media_id,path,expected_source=None,*,review=None,context=None)` now requires a successful review; explicit context/path/target must match it. An optional expected_source is checked against the review and remains insufficient by itself. Both application methods send actor/client, validate the acknowledged physical source/owner and never automatically retry uncertain writes.

```python
review = filmocity.inspect_relink(media_id, replacement_path)
# Present review["issues"] and review["summary"] for explicit review here.
# Only after the user authorizes this exact compatible replacement:
if review["ok"]:
    result = filmocity.apply_relink(review)
```

MR01–MR16 in [Windows acceptance](WINDOWS-TEST-HANDOFF.md) cover this workflow. Preview preparation, original export, source-wide color and audio-channel fidelity require separate native checks; controlled callback/store/probe evidence does not establish release readiness.

## Owned editorial source commands and canonical Describe

`POST /api/graphics/split_words`, `POST /api/media/input_transform` and `POST /api/media/extract_audio` now require an acknowledged `_context` (`workspace`, `project`, `revision`). Send `actor` and `client` for identity/policy. These are direct commands, not Prepare/Review/Apply jobs: the server plans privately, revalidates ownership/resources/policy and saves a changed command in one Undo transaction. A no-op leaves revision/history unchanged. Do not replay a mutation after an unknown response; reconcile saved state and Recovery first.

Split Words keeps `{sequence,clip_id,layer,anim?,stagger?}`. `layer` is the explicit text-layer index; the track must be unlocked. `stagger` defaults to 0.12 seconds. Omitted `anim` preserves the current entrance, or supplies a disclosed default when absent; `{}` clears it. The Graphics UI deliberately sends `{type:'pop',duration:0.35,ease:'back_out'}`. Supported selected-layer transform/opacity curves copy to each word and later `gN.*` curves retain their original layer ownership. Exit animation is copied without adding entrance stagger. Canonical clip duration bounds the full animation; unsupported aggregate typography/effects refuse atomically. Basic multiline layout, including interior blank lines, uses resolved-font geometry. Empty/single-word text is a no-op. Bounds include 100 words, 256 resulting layers, 10,000 characters, 600-second graphics, 240 fps, 8,192 points per curve, 32,768 expanded points, 200,000 control commands and four MiB of graphic metadata.

Input Transform keeps `{media_id,transform}` with `none|slog3|vlog|clog3|logc3`. A subclip resolves to its physical picture source; the response identifies requested/physical IDs, `affected_media_ids` and `scope:'shared_source'`. This intentionally affects every use, including locked-track clips. Clearing/changing conversion updates its LUT binding while preserving unrelated source metadata. The existing source-color inspector already uses its guarded physical-parent edit path; this route migration does not create a second clip-local color scope.

Extract Audio keeps `{media_id}`. It registers an audio-only alias of the original file, retains the selected logical window/interpretation and gives preparation its own ID, token and files. It does not create an exported WAV. `audio_alias` has `{version:1,source_media_id,physical_media_id}`; `subclip_of` names that physical parent, `sub_in` is logical offset and `duration` is logical length. The own preview spans the complete native source clock, so source-coordinate conversion remains `(logical + sub_in) / interpretation_factor`. Preview metadata declares first-stream AAC, lossy stereo at 48 kHz and `validation:'audio_alias_common_clock_metadata'`; ordinary export continues reading original audio. Newly registered aliases begin unprepared until their owned worker starts. If post-save queueing fails, inspect returned preparation warnings and explicitly Prepare. Source files above four hours and unsupported generated/image-sequence inputs refuse. Already-audio-only input is a no-op. Relink the physical parent to accept source changes; Prepare recaptures accepted current inputs, while Retry reuses the old captured task and refuses changed inputs. Alias-range edits never authorize changed file bytes. If parent interpretation changes, recreate the alias rather than silently changing its existing source clock. Alias preparation uses per-stage 180-second FFmpeg timeouts, not a total-job deadline.

Successful command envelopes include `ok`, `context`, `summary`, `warnings`, `changed` and saved `project` identity. Split adds sequence/clip/layer-count fields; input conversion returns the physical media and shared affected IDs; extraction returns the alias media/ID, original source ID and post-save `preparation` outcome. Treat the acknowledged context and returned summary as authoritative. Frontend controls wait for saved changes, avoid optimistic mutations and retire undispatched work after Escape/owner/selection/control changes. Closing after submission cannot cancel a committed change.

**Describe migration:** `GET /api/sequence/describe` now requires all four query fields: `sequence`, `workspace`, `project`, `revision`. Encode them from one acknowledged saved owner. A missing, stale or foreign owner refuses; the route never substitutes the currently active sequence. The read-only response includes exact `context`, `sequence`, `text`, `duration`, `clips`, `sections`, `timings`, `clock:'timeline-seconds'`, `frame_rate` and `frame_policy`. Each timing has `clip_id`, `track_id`, `kind`, full-precision `start/end/duration`, `source_in/source_out`, `hold/reverse` and containing-frame `start_frame/end_frame`. Rational rate and canonical renderer duration account for ramps, holds, reverse and nesting; text prints six decimal seconds. Check response owner/sequence before displaying or copying it. Reads do not create history.

SDK signatures: `describe(seq_id=None, *, context=None)`, `split_words(clip_id, layer_index=0, anim=None, stagger=0.12, seq_id=None, *, context=None)`, `input_transform(media_id, transform, *, context=None)` and `extract_audio(media_id, *, context=None)`. Without an explicit context the client captures ownership once; an explicit context requires an explicit sequence for sequence methods. No uncertain write is retried automatically. SW01–SW08, IC01–IC06, EA01–EA08 and SD01–SD04 remain native acceptance requirements; controlled Linux evidence is in [the current checkpoint](MODERNIZATION.md).

## Composed Cover, Explainer and explicit Hook Variants

Explainer and Variants extend the owned recipe contract below with modes explainer and variants. POST /api/recipes/explainer or POST /api/sequences/variants requires captured sequence, saved _context and unique lowercase 32-hex request_id. Send actor/client for identity and policy. Both queue kind recipe; use POST /api/tasks/{id}/recipe to Review, then existing Apply with exact reviewed context/fingerprint. All cards/copies and the application receipt save in one Undo transaction. Prepare/Review/no-op never adds project history.

Explainer settings: lower_third null or {name,role,at,duration}; name is required nonempty and role optional, both up to 200 characters; position is finite from 0 to ten days, duration from 1e-6 to 60 seconds (default 4.5). chapters is boolean (default true); chapter_duration and end_duration are from 1e-6 to 60 seconds (default 3); end_card is up to 500 characters. At most 256 chapter cards are planned. Cards use canonical sequence duration and inward whole-frame bounds, with explicit shortened/skipped/overlap warnings. New upper tracks preserve all existing clips/locks/overlaps.

Variants settings: hooks (1–20 nonempty strings up to 500 characters), targets (1–100 distinct explicit {clip_id,layer} or {clip_id,title:true}), optional nonempty name_prefix up to 120 characters (default source name). Layer is a nonnegative integer pointing to text. Missing, ambiguous or locked targets refuse; there is no fallback text selection. Copies preserve unrelated text/captions and advanced source processing, remap local identities/references, preserve scoped foreign references/provenance and clear old applied-task receipts. Nested dependencies remain shared, disclosed in Review. Apply returns the first created sequence; summary.variants lists every destination.

Cover queues kind cover through POST /api/recipes/cover with saved _context, request_id, sequence, finite time before sequence end, headline (up to 500), sub (up to 1000), template name (up to 120; default Hook — Big Statement), framing (cover/contain/blur_fill; default blur_fill) and optional sizes (default current canvas). Sizes are 1–4 unique integer [width,height] pairs, each axis 16–4096 and aggregate at most 32*1024*1024 pixels. Empty text yields frame-only output. The complete authored source frame is rendered first; original titles/captions/effects remain in that composition.

POST /api/tasks/{id}/cover with _context returns task, context, result and read-only plan (empty ops, summary, fingerprint). Result version 1 includes kind cover, captured sequence/time/frame/context and covers descriptors (index,width,height,filename,url,size,sha256). PNGs stay under the owned task. GET /api/tasks/{id}/cover/{index} requires workspace/project query fields matching the captured owner; optional revision requires the exact reviewed saved revision. download=1 selects attachment disposition. Both review and image routes revalidate source/resource/artifact identity; a switched owner, cancelled task or changed dependency refuses. A Cover task has no project Apply.

SDK: start_recipe('explainer'|'variants',...), recipe_result, wait_recipe and apply_recipe share the existing owned contract. explainer(...,preview=True) and variants(hooks,targets=[...],name_prefix=None,preview=True) default to review; explicit preview=False applies once. start_cover(sequence=None,time_s=0,headline='',sub='',sizes=None,template='Hook — Big Statement',framing='blur_fill',context=None,request_id=None), cover_result, wait_cover and cover(...) render/review without project mutation or local file writes. download_cover(task_id,index,reviewed) explicitly returns verified PNG bytes, uses the reviewed owner/revision and a constructed API URL, checks size/hash/IHDR geometry and never automatically retries or requeues. Refresh Review after a changed revision. Keyword-only parameters follow actual signatures.

Cover budgets and the native verification procedure are in WINDOWS-TEST-HANDOFF.md. Sources/resources use stat identities; generated PNGs use SHA-256. Generated text uses scaled line spacing, bounded resolved-font metric shrinking/refusal and opt-in drawtext bounds correction; text that cannot fit requires shorter text or a larger canvas. Font shaping, decoration bounds and inter-layer layout remain approximate. Outputs use existing 8-bit RGB rendering; no native/HDR/fast-seek guarantee is implied. CV01–CV08, EP01–EP07 and HV01–HV07 remain mandatory native acceptance.

## Owned audio measurement, gain and transient markers

`POST /api/audio/peak`, `/api/audio/measure` and `/api/audio/beats` now queue kind `audio_analysis`, with modes `peak`, `loudness` and `beats`. They no longer synchronously return unowned measurements. Supply `_context`, a 32-character hexadecimal `request_id`, and either `{sequence, clip_ids:[...]}` or read-only raw `{media_id, in?, out?}`. Raw bounds are logical source seconds. Gains allow 1–50 clips; markers require one. Analysis permits ten minutes per item or rendered nested dependency, processed sequentially, with separate aggregate one-hour rendering and native-decoding budgets. Each native input span is at most ten minutes; shared-input gaps, up to two seconds of seek preroll and 0.1 seconds of postroll count toward decoding work. Measurement uses a scoped source-origin-preserving seek, so a short range late in a long source remains usable. Full nested source duration and native inputs participate even when the outer selection is short; custom decoder input options refuse. Normalization uses `target` in −40…0 dBFS/LUFS; beat marker spacing uses integer `every` in 1…128. A marker interval does not identify musical meter.

Poll Tasks, then `POST /api/tasks/{id}/audio` with current `_context` to obtain `{task, context, result, plan}`. Result version 1 has `kind:"audio_analysis"`, `mode`, `scope:"timeline"` or `"media"`, `clock:"clip-local"`, captured sequence/clip/source identities, signature and `measurements`. Each measurement reports its ID, duration, 48 kHz stereo format, nullable decoded `peak_db`/`rms_db` and `integrated_lufs`/`true_peak_dbtp`/`loudness_range_lu`, `silent`, candidate `beats`, nullable estimated `bpm`, numeric `tempo_confidence`, `resolution`, `method` and warnings. Read the reported scope: raw range candidates are relative to the requested window, not absolute parent-file timestamps. Digital silence has null peak/RMS; modes other than beats have no BPM estimate. No downbeats are inferred.

Timeline normalization measures isolated rendered clip audio, including channel selection, pan, source timing and live clip processing; parent track/master processing and tails beyond the clip end are excluded. Apply shifts base gain and all manual-gain anchors together. Existing piecewise average-speed audio and 128-sample gain control blocks remain renderer limitations. Silent/gated values cannot authorize normalization. Loudness overload warnings do not add a limiter or certify final mixed output.

`plan` includes exact `ops`, a visible `summary` and `fingerprint`. Raw plans have no edits. For a timeline plan, explicitly `POST /api/tasks/{id}/apply` with the reviewed `_context`, `fingerprint`, `actor` and `client`. The server revalidates source/target ownership and policy, rebuilds the plan, and saves one receipt/history transaction. No-op plans add no history. Changed owners, files, locks, unsupported inputs or invalid later batch members refuse. After an uncertain mutation response, inspect the saved project/task and use Recovery; never automatically replay.

`POST /api/audio/gain` handles manual gain without analysis: `{_context, sequence, clip_ids, mode:"set"|"adjust", value, actor, client}`. Set chooses the new base gain; Adjust adds the requested delta. Both preserve the relationship between base gain and every stored manual-gain anchor, including offscreen anchors. Every resulting base/anchor must remain between −40 and +24 dB. The complete batch saves once or refuses; no clamping, half-decibel rounding or overlap normalization is performed.

SDK: `start_audio_analysis(mode, media_id=None, sequence=None, clip_ids=None, in_=0, out=None, target=None, every=1, context=None, request_id=None)`, `audio_result`, `wait_audio_analysis`, `apply_audio_analysis`, `set_gain(clip_ids, value, mode="set", seq_id=None, context=None)`, `normalize_audio(clip_ids, target=None, mode="loudness", seq_id=None, preview=True)` and `add_beat_markers(clip_id, every=1, seq_id=None, preview=True)`. `loudness`, `peak` and `beats` wait for managed read-only source results and return the canonical result with `measurements`; callers must migrate from the old direct measurement/downbeat shape. Convenience normalization defaults to −18 LUFS or −3 dBFS peak. Waiting uses a finite timeout and never resubmits. Keyword-only arguments follow the source signatures; explicit `preview=False` authorizes the reviewed timeline Apply. Native Windows/HTTP/device behavior remains unqualified.

## Canonical source replacement and owned Synchronize

`POST /api/clip/replace-source` requires current `_context`, `sequence`, `clip_id`, `media_id`, logical `in` and optional logical `out` cap. The server recomputes a complete source replacement and validates the target/source/locks; it retains the original timeline duration and timing model. The `out` request is an available-source cap, not the new clip Out. Ordinary replacement uses new Out = lower In + original source span, including reverse/ramp models; a held frame validates its frozen In while retaining its duration. Stills retain virtual length. Genuine source/window changes clear stale restoration/bake ownership and hidden source markers while retaining active local annotations and effects. Exact no-ops do not add history. Detached pairs, foreign-media stabilization, unsupported new synthetic sources, invalid parent/interpretation metadata and insufficient source refuse. Use one saved transaction/Undo; reconcile unknown responses through Recovery rather than replay.

`POST /api/audio/sync` now queues kind `sync`; it does not directly return offsets or move clips. Supply `_context`, a unique `request_id` and either `{sequence, clip_ids:[reference, ...targets]}` or read-only raw `{media_ids:[reference, ...targets]}`. Poll the owned task catalog. `POST /api/tasks/{id}/sync` with current `_context` reviews the completed task and returns `{task, context, result, plan}`. Result version 1 has `kind:"sync"`, `mode:"timeline"` or `"media"`, `clock:"timeline-local"`, captured IDs, explicit reference, finite offsets, per-source matches and warnings. Positive offset means the target begins later. Match quality includes correlation, overlap, confidence, resolution and method; resolution is search spacing, not an accuracy guarantee. Two to eight mono/stereo sources, at least two seconds of useful overlap, the first 120 timeline/180 native seconds, forward constant speed and equal effective native rates define this implementation. Silent/ambiguous, reverse/ramp/hold and rate-mismatched sources refuse.

Timeline review includes proposed moves, grid residuals and a fingerprint. Apply through `POST /api/tasks/{id}/apply` with that exact `_context` and `fingerprint`; the server rebuilds the plan and saves one Undo transaction/receipt. Picture moves quantize to the rational sequence frame grid; audio to 48 kHz samples. Negative starts, collisions, stale targets/sources, locks and separated grouped/detached partners reject. Raw review has `plan.ops:[]` and no timeline Apply. UI multicam/merge creation separately refreshes raw source review before a guarded single sequence insertion; it displays picture/audio rounding and preserves full heads with a shared nonnegative shift.

SDK methods: `replace_source(clip_id, media_id, in_=0, out=None, seq_id=None, context=None)`; `start_sync(media_ids=None, sequence=None, clip_ids=None, context=None, request_id=None)`; `sync_result(task_id, context=None)`; `wait_sync(task_id, timeout=900, poll=0.5, context=None)`; `apply_sync(task_id, reviewed)`; `sync(media_ids, timeout=900)` for read-only raw results; and `synchronize(clip_ids, seq_id=None, preview=True, timeout=900)` for selected timeline clips. Keyword-only parameters follow the SDK signatures. Preview/review is the default; explicitly apply only after reviewing offsets and limitations. Timeout/error does not authorize resubmission. These routes do not qualify native device alignment, nonlinear/drifting recordings or every legacy recipe/nesting command.

## Source metadata and XML timing

Newly probed/imported/relinked media includes `sample_rate`, `channels`, `channel_layout`, `audio_streams` and `frame_rate` (a rational string such as `30000/1001`, or null). Unknown values remain null; older project records may lack them. Summary audio fields describe the first audio stream. The VFR flag compares declared average/nominal rational rates; it is not a full timestamp analysis. Probe errors/timeouts fail explicitly.

`POST /api/import/fcpxml` accepts `{xml, _context?, actor?}` for **FCP7 xmeml**, not modern FCPXML. New clients should supply the saved project context. Legacy requests capture the active project before inspection and still reject concurrent edits. Sources are registered and sequences committed together with one undo step; preparation queues afterward. The response includes `ok`, `context`, `sequence`, `sequences` and `message`. Missing source files, invalid rates/XML, transition-dependent bounds, retiming and nonzero mixed-rate offsets return 400 without a project commit. A project conflict returns 409. An uncertain mutation reply must use the existing Recovery flow rather than automatic replay.

FCP7 XML uses rational NTSC boundary conversion and escaped file URIs (including Windows drive/UNC paths). Common decimal NTSC aliases map to their broadcast rational rates. Unsupported export rates/retiming return 400. Source audio fields are only emitted when measured; the sequence mix format remains the existing output policy. Straight-cut round-trip checks are not proof of full NLE interoperability. Effects, complex nesting, EDL/OTIO semantics and capability reports remain under review. SRT/VTT times round to whole milliseconds with proper carries.

## Mixer operations

Use `PATCH /api/project` with the saved `_context` and an operation such as:

```json
{"op":"set_mix","sequence":"seq1","track":"A1","changes":{"gain_db":-6,"muted":false,"solo":true}}
```

`track:null` targets the sequence master and permits `gain_db` and `audio_fx`; track buses also permit boolean `muted` and `solo`. Gain must be a finite JSON number from -96 to +24 dB (not a numeric string or boolean). Existing sequence/track IDs must be unambiguous. Video tracks are only valid targets when they are their own audio destination; otherwise use their matching/fallback audio track. Timeline track lock does not disable these bus controls. There is no implicit track creation or automatic selection of another sequence.

`audio_fx` replaces that target's processing object, preserving the other bus/master fields. Read its current value, merge changes with extensions, and submit against that captured context. Known fields are validated: EQ low/mid/high -12..12 dB; compressor enabled boolean, threshold -60..0 dBFS, ratio 1..20, attack 0.01..2000 ms, release 0.01..9000 ms and makeup 0..36 dB; denoise enabled boolean and reduction 1..40 dB; limiter boolean. Unknown processing extensions are retained but not interpreted. Existing unrelated values are not migrated or clamped automatically.

Pure `set_mix` batches do not normalize clip overlaps. Mixed/other batches retain existing normalization. Each submitted batch uses the existing project/history transaction and exact Undo/Redo; invalid later operations do not partially commit. IDs are resolved on the captured saved project, never rebased to the current track index. Missing context is 400, invalid controls/targets are 422, and stale context is 409. Postcommit log/broadcast faults return `ok:true`, saved `context` and `warning`. An uncertain reply must use Recovery, not automatic replay.

The existing SDK can send `cr.patch([operation], context=state["context"])`. Mixer operations can also be proposed through `cr.propose(..., context=state["context"])`; new mixer proposals require context and their preview/accept preserves overlap timing. Direct non-human patch requests still honor proposals-only mode and now fail closed if editing preferences cannot be read. Do not use actor labels to bypass the configured collaboration workflow.

## Reviewed music ducking

`POST /api/audio/duck_all` now requires `{sequence, _context}`. Optional fields: `music_tracks:[id,...]`, `dialogue_tracks:[id,...]`, `mode:"apply"|"remove"`, `preview:boolean`, `preview_plan`, `actor`, `amount` (-60 to -0.1 dB), `attack`/`release` (0.001–10 s), and `hold` (0–10 s). `music_track` is a single-track compatibility alias when `music_tracks` is absent. Legacy `fade` supplies omitted attack/release; otherwise their defaults are 0.15/0.5 s, with amount -12 dB and hold 0.1 s. IDs must exist and be distinct; music targets must be unlocked audio tracks, disjoint from dialogue tracks. Remove needs no dialogue/settings and removes only `audio.duck_db`.

Omitted track lists suggest linked-video tracks without music tags and tracks containing a dialogue-tagged clip (`audio_tag:"dialogue"` or `tags:["dialogue"]`); other populated audio tracks become music. This is a track heuristic, not classification. Explicit track choices are recommended, especially for separate voiceover/mixed-purpose tracks. Audible routing still excludes muted, non-solo, disabled, unlinked video and held clips. Nested audio covers the whole parent clip span.

Send `preview:true` first. The response includes `ok`, unchanged saved `context`, `sequence`, `plan`, `preview:true`, `ducked` (changed clips), `affected`, `points`, `dialogue_clips`, `dialogue_spans`, `skipped`, selected track lists, `settings` and `message`. Apply with the same body, returned context/sequence, `preview:false` and `preview_plan:plan`. The UI always uses this review contract; direct API use can omit `preview_plan` but must still supply saved context. Choice/context changes are rejected rather than rebased. Each changed Apply/Remove is one history transaction; unchanged plans do not write history. Postcommit notification errors return success with `warning`; an unknown reply must be reconciled through Recovery, never automatically replayed. Non-human direct mutations respect proposals-only mode; review remains available.

`cr.duck_all(..., context=review["context"], seq_id=review["sequence"], preview_plan=review["plan"])` preserves an explicit basis and requires its sequence ID. Without `context`, the SDK reads project+context together and validates the requested sequence; it never falls back from an unknown ID to the first sequence. SDK `fade` retains its historical 0.35 s default. Explicit attack/release override it. All requests need authenticated API access as configured for the server.

Manual `audio.gain_db` remains untouched; additive `audio.duck_db` is clip-relative, linear/hold, -60–0 dB, at most 8,192 points per clip and 65,536 generated points per plan. Applying again replaces this separate ducking layer. Clip-span automation includes internal silence and must be regenerated after timing edits; it is not speech detection or a live sidechain. Old gain curves overwritten by legacy ducking are not restored by Remove.

## Background preparation, transcription and collection API

`GET /api/tasks` returns the active storage project's `context`, `tasks`, `workers`, `capacity`, `total` and unreadable-history warnings. The preparation pool has two workers and permits one transcription at a time; exports remain in their existing queue. Task states are `queued`, `running`, `cancelling`, `publishing`, `ready`, `applying`, `done`, `applied`, `cancelled`, `error`, `interrupted`. Stage progress may be null. Admission is capped at 256 active jobs; history is retained separately.

- `POST /api/tasks/transcribe`: `{sequence, model, _context, request_id?}`. Use the current saved context. Optional request identity is exactly 32 lowercase hex characters; preserve it for an identical request whose reply was lost. Same active/ready semantic input deduplicates even across presentation/derived-metadata changes. Missing ASR returns 501 before admission. Returns `ok`, `task`, `context` and a message immediately after durable admission; it never edits a sequence.
- `POST /api/tasks/{id}/apply`: `{_context, actor?}`. Ready transcription or collection, owned by the active project; see Original-media collection tasks for copy/hash/relink semantics. Transcription validates the captured sequence/nested dependencies, prior transcript and source stat metadata, then commits transcript/project/history together. Caption edits remain and receive review flags. A task marker makes a repeated, already-committed apply idempotent. Changes to audio/edit dependencies return 409 and retain the downloadable result. Read-only source files are not copied or hashed; identical-size/mtime external replacement is outside this validation.
- `GET /api/tasks/{id}/result`: JSON attachment with task record and completed result. No project mutation. Download while the original project is active.
- `POST /api/tasks/{id}/cancel`: no body needed. Queued work never starts; running work cancels cooperatively. Ready transcript or collection results may be discarded; collection copies are retained. Publication/apply in progress returns 409. Speech native operations must return before cancellation completes.
- `POST /api/tasks/{id}/retry`: `{_context, request_id?}`. Only failed/cancelled/interrupted work; current source/dependencies must match. Returns a new task with `retry_of`; duplicate active inputs may return their existing task.
- `POST /api/tasks/media/{media_id}/prepare`: `{_context}`. Prepare a registered source generation again, including after queue admission failure. Older entries without an ingest token need relinking first. Imported originals remain after failures.

Receipts are checksummed with previous copies, scoped to the owned workspace. Ready/applied results survive restart; unfinished work is interrupted without automatic replay. Interrupted apply returns ready with an outcome-check message; the project marker prevents a second mutation if commit succeeded. Persistence failure after admission produces a visible warning; a restart may only recover the preceding checkpoint. Corruption is preserved. Task status/result APIs use storage-project ownership, not document IDs. Earlier synchronous transcription endpoints remain for compatibility and do not use this pool; new UI entry points use these task routes.

## Guided workflow API

Read `GET /api/project/state` and pass its full `context` as `_context`. These routes require the captured saved version; omission is not a legacy opt-out. All successful mutations return `{ok, context, message, warning}` and use one project/history transaction. Sequence-producing actions also return `sequence` and `sequences`. A 409 rejects a changed project; an uncertain network/5xx outcome must be inspected before replaying the action.

- `POST /api/workflow/action`: `{action, sequence, _context, ...}`. `assemble` takes ordered `media_ids`, `name`, `format` (`landscape`, `portrait`, `square`) and `fps`; it creates a new sequence. `story` takes selected zero-based transcript `words`, optional `name` and `padding` (0–0.5 seconds); it creates a new cut and preserves the source. `cleanup` takes `clip_ids`, `highpass` (40–180 Hz), `denoise` (0–18 dB) and `ratio` (1–6); it replaces only workflow-owned dialogue effects. `captions` takes `max_words` (2–16) and `style` (`clean`, `boxed`, `highlight`), replacing captions and their style. `versions` takes distinct `formats` and `fit` (`contain` or `cover`); it creates independent nested content copies and delivery sequences.
- `POST /api/workflow/action` also accepts `transcript_edit` with `edits:[{index,expected,text}]`: 1–500 unique zero-based indices, exact original word and one corrected word (1–120 characters). It preserves timings/confidence and returns `words_changed`, `captions_updated`, `captions_to_review`. Invalid/stale batches never partially apply. Untouched generated captions carry `workflow_words` and `workflow_text`; independent edits are preserved and flagged in `sequence.workflow.caption_review_ids`. `caption_review` takes `caption_ids` from that pending list and acknowledges only those IDs. Both actions require the captured context and use one undoable transaction.
- `POST /api/workflow/transcribe`: `{sequence, model, _context}`. Supported models: `tiny`, `base`, `small`, `medium`, `large-v3`. Default `base`. Produces word timings without overwriting captions unless `captions:true` is supplied. Requires the optional local speech engine; missing tools return 501 with setup instructions before rendering audio. No words detected returns 400. Slow work captures the project first and revalidates before committing. Recorded timing fingerprints include nested dependencies; later timing edits invalidate transcript-based cuts/caption generation. Legacy `/api/transcript` and `/api/captions/auto` now also capture, revalidate and commit undoable results, even when an older caller omits `_context`.
- `POST /api/workflow/import`: multipart `files`, with JSON context in the `X-Filmocity-Context` header. Imports 1–100 files as a batch under unique, sanitized workspace destinations. Copy/probe work runs outside the project lock; a stale project rejects the entire batch. No failed batch is partially registered. Successful replies include `added` media IDs. Thumbnails/proxies complete separately with the captured project identity. Import undo/redo receipts track these derived fields without ignoring ordinary edit conflicts. Files remain after undo and uncertain disk commits.
- `GET /api/captions/export?sequence=...&context=<JSON>` optionally binds SRT download to an exact saved context, rejecting stale/cross-project links. Older callers may omit context.

See [the workflow guide](GUIDED-WORKFLOW.md) for selection behavior and explicit scope limits. The packaged executable cannot run itself as a pip installer; missing packaged speech dependencies return setup guidance, not a successful install. Native speech packaging is still pending.

Queued exports now reserve `renders/job-<id>/` directories. Always use the job's `out`/`frames` URLs; names no longer imply flat paths. `command_log` identifies its UTF-8 command log and `review_url` identifies its canonical review page. Deliverables rows include `job_id`. Repeated names and case/sanitization collisions produce independent destinations; direct renderer callers still manage their explicit output paths. Queue inputs are detached snapshots, but external media bytes are not frozen. New jobs checkpoint history inside their own folders and restore on reopening the same canonical workspace. Completed records retain job/review identity; queued/running/cancelling records become interrupted errors without automatic requeue. Failed/cancelled records keep their saved error. `history` reports restored/recovered/unreadable states and persistence warnings; `recovery` describes interrupted or unavailable outputs. Completed restoration compares size/mtime (`output_check: "metadata_only"`), with only the manifest and first frame checked for PNG. It does not decode/hash all media. Invalid receipts fall back to a previous valid record or an explicit error; files stay untouched. Older unrecorded outputs and moved libraries are not automatically adopted. Restored previews lose active preview/request identity. `/api/jobs` returns the latest 50 entries; older records remain accessible by job ID. Receipts do not contain a resumable project/media snapshot.

Review endpoints accept `job-<id>` as their reference. Legacy name lookup succeeds only when unambiguous. Comment reads/writes require the originating project to be active and the sequence to exist. New markers carry `review_job` and `review_time`; `time` is the sequence position including the captured In offset. Notes use the normal reversible project transaction. Later timeline edits do not rebase them. A saved-note response can include `warning` for audit/notification problems.

Before exporting, use `POST /api/render/preflight` with `{sequence, preset, all_sequences?, _context?}` (SDK: `preflight()`). The read-only report includes `ok`, error/warning counts, and issues with sequence/track/clip/media identity and resource paths. Originals, numbered frame continuity, nested references, graphics, LUTs and font files are checked. A playback proxy does not satisfy an original-source requirement. Availability checks do not prove full decode or creative quality. Missing resources return HTTP 422 before a render job is queued; workers check again when they start. Batch export checks every selected sequence before queuing its first job. H.264/HEVC delivery profiles also run a bounded device encode/metadata/decode check using the selected encoder; failures produce an `encoder_unavailable` issue and do not silently select software. Reports carry the captured `context`; send it as `_context` on `/api/render` or `/api/render_all` so intervening edits/switches fail with HTTP 409. Jobs and their audit events retain the captured project. Fixed-codec/image/audio and existing internal lossless presets do not use this delivery probe.

## PNG sequence results

`POST /api/render` with `preset.format: "png_sequence"` publishes a validated directory of numbered PNG frames. Poll `GET /api/render/{job}` (or read `GET /api/jobs`) until `status: "done"` before opening output links. A finished job includes:

```json
{
  "status": "done",
  "output_kind": "png_sequence",
  "out": "/renders/example.frames/sequence.json",
  "frames": {
    "directory": "/renders/example.frames",
    "pattern": "frame_%05d.png",
    "first_frame": "/renders/example.frames/frame_00001.png"
  },
  "qa": {
    "status": "checked",
    "output_kind": "png_sequence",
    "frame_count": 12,
    "width": 64,
    "height": 48,
    "frame_rate": 24.0,
    "duration": 0.5,
    "size_mb": 0.02,
    "flags": []
  }
}
```

This is an illustrative response; measured QA values vary. `out` is the **Sequence manifest** JSON link; `frames.first_frame` is the **First frame** image link. The export dialog and Render Queue label this result **PNG sequence** and display available frame count, dimensions, duration and total frame size. Missing fields are omitted. Single-file exports retain their file link (Render Queue: **Open**).

The manifest records the filename pattern, first frame filename, frame count, dimensions, numeric frame rate, timeline duration in seconds and each frame's `{file, size, sha256}` (size in bytes). Sequence QA `size_mb` is the sum of PNG frame bytes in decimal MB, rounded to two decimals, excluding the manifest; `qa.sha256` hashes the manifest bytes. Frame count follows the renderer's rounding of duration × frame rate, so duration need not equal frame count ÷ frame rate. A PNG sequence has no audio stream or loudness measurements. Consume only fields actually returned; render QA does not establish creative approval. Progress and cancellation use the existing job endpoints. Publication/cancellation limits are documented in [RELIABILITY.md](RELIABILITY.md).

## Governance
The human chooses in the header whether agents may edit directly or must propose. Under **proposals only**, `PATCH /api/project` from any non-human actor returns **403** with the message to use `POST /api/proposals`; the SDK raises `FilmocityError` — catch it and fall back to `propose()`. Check `GET /api/settings` → `agent_mode` before a long session. Send `POST /api/events {type:"focus", t}` (SDK `focus(t)`) to show the human where you are working.

## Proposals are previewable
The human can press **Preview** on one item or **Preview all** to inspect a separate prepared frame review without changing the editor; write proposals whose visual intent is clear from a single frame when possible, and put the reasoning in `reason` and in the affected clip's `note`.

## Reading the human
Before proposing, call `GET /api/session/summary?since=<your last read>`: it tells you which tools the human used, which clips they touched, which ranges they replayed (attention), what they accepted/rejected and why (reason codes), and the brief. Write proposals against that context; keep `reason` short and concrete — it is shown on the timeline ghost and stored with the decision.

## The intended loop
1. Agent imports media, builds a cut with `PATCH` ops, then `POST /api/snapshot {label:"agent_proposal", actor:"agent"}` (after the proposal is complete). Optional preview render.
2. Human edits in the UI (every action logged with tool + before-state) and/or the agent posts **proposals** for specific changes with reasons; the human accepts/rejects each.
3. Human presses **Mark as human final** → diff pair logged. The agent reads `training/edit_pairs.jsonl`, `training/proposal_decisions.jsonl`, `events.jsonl` and `annotations` to learn preferences per brand and per format.
4. Export (deterministic from JSON) or hand the cut to Premiere via XML when needed.
Rules: `actor:"agent"` and a human-readable `reason` on every write; prefer proposals over direct `PATCH` once a human has started editing; never `PUT` while a human is active.

## Runtime identity

`GET /api/version` retains `app`, `version` and `schema`, and adds `instance` (per-launch nonce), `pid`, `workspace` (the hashed data-root identity used in project context) and `build`. Normal source runs return `build:null`; the candidate builder embeds `{id, source_sha256}`. The route remains accessible for startup checks when API authentication is configured. These fields identify a running instance; they do not certify a release. Separately, backend startup now takes an exclusive OS lock on the data folder before migrations or project access. A competing cooperating process exits instead of starting another writer. Use one backend per library; older releases and external tools do not honor this guard. Launchers compare nonce, PID and workspace before showing the UI.

## Saved snapshots and automatic backups

`GET /api/projects/versions?kind=snapshots` (or `kind=backups`) returns `{kind, context, versions, unavailable}`. Each readable version has `file`, `sha256`, `ts`, `label`, `name`, `sequences` and `clips`; unreadable entries carry a filename and reason. `context` is the saved project identity/revision at inspection. Existing `/api/snapshots` and `/api/backups` still return arrays, now with validated entries and hashes; snapshot order remains oldest first, backups newest first. `/api/snapshots/get?file=...` returns a validated project.

Restore with `POST /api/snapshots/restore {name, sha256, _context, actor?, client?}` or `POST /api/backups/restore {file, sha256, _context, actor?, client?}`. Send the original inspected context and hash, not a freshly read replacement context for an old selection. Conflicts return 409 before restore. A supplied `_context` requires a file hash. Legacy omitted-context/hash calls remain supported against the active project when the store lock is acquired; they do not establish selection-time protection.

A successful restore returns `{ok:true, context, file, sha256, preserved, warning}`. `preserved` names the checkpoint in the same project's snapshots. Restore uses the project/history journal and creates one undo entry. Current or history corruption requires Project Recovery instead. The selected automatic backup is exempt from pruning during this restore; normal rolling retention resumes on later saves. The restored schema is migrated if necessary; referenced media is not copied. A warning can report secondary log/notification failure after the restore already committed. Never replay after an unknown network outcome: inspect the project and Recovery copies first.

`POST /api/snapshot` accepts optional `_context` and `client` alongside the existing label/actor/sequence. It returns `ok`, unique `snapshot` ID, `sha256`, unchanged project `context`, optional training `pair` and `warning`. New snapshot filenames retain the timestamp/label convention with a random component to avoid overwrites; use returned IDs instead of constructing filenames. The SDK supports `snapshot(label, seq_id, context=captured_context)`; omitting context keeps the older calling convention. An invalid explicit context never falls back to an unguarded write.

## Original-media collection tasks (unreleased source)

`POST /api/tasks/collect` and its alias `/api/projects/collect` now require `{_context, request_id?}` from the acknowledged saved project. They return `{ok, task, context, message}` and do not relink. This intentionally replaces the old immediate-commit contract. Request IDs are 32 lowercase hexadecimal characters, as for other task submissions. A matching existing request returns its existing task; changed inputs with the same request ID are rejected. Media identities/file stamps are captured off the event loop and the project context is checked again before queue admission.

The `collect` task checks original file identities, copies/hashes complete originals (including numbered sequences), publishes an exclusive collection generation and becomes `ready`. Its public result includes `folder`, `manifest`, `manifest_sha256`, `copied`, `reused` and `verified`. The downloaded result also includes the prepared media paths. `GET /api/tasks/{id}/result` returns a `collection-receipt` attachment. All management/result endpoints require the owning project to be active. Collection excludes external graphics/fonts/LUTs and other non-library resources; portable project packages provide that workflow.

`POST /api/tasks/{id}/apply {_context, actor?}` explicitly verifies the manifest and copied-file hashes, rejects changed library identities or accessible replaced originals, then rechecks the active saved context before committing paths, proxy signatures, a task marker and history as one transaction. Offline originals are allowed after a verified copy. Timeline/presentation changes made since preparation are preserved. Success returns `{ok, context, message, warning}`; one Undo restores old paths and leaves copies on disk. An already committed task marker reconciles a lost reply without applying again. If Apply is undone, use Redo rather than replaying an already-applied task.

Cancel queued/running work through the existing task endpoint. Cancel on `ready` keeps the current project and published copies/receipt; it does not delete media. Retry a failed/cancelled/interrupted task explicitly with the current context and a new request ID; its captured library must still match and the worker revalidates original stamps. Completed copies survive restart and never auto-apply. An interrupted publication may leave recoverable files without a completed receipt: inspect before retrying. Neither a task receipt nor stat stamps establish protection against hostile filesystem races, and blocking filesystem calls have no hard cancellation deadline. Collection task JSON and each manifest are limited to 32 MiB; an oversized manifest is refused before publishing copies.

## Project lifecycle (unreleased source)

Open, New, Save As, Duplicate and Sample require `_context` from the saved source returned by `GET /api/project/state`. Complete pending writes first and use their acknowledged context. Omitted or stale contexts are rejected; these routes have no legacy omitted-context fallback. Names must contain 1–240 characters after trimming, without control characters. New optionally accepts boolean `copy_media`; this copies bin references, not independent resource files.

`GET /api/projects` returns literal display names and storage IDs, the active flag, sequence/media counts, modification time, and `file_sha256` when readable. Invalid projects remain listed with `error`. Recent returns the first twelve entries. Send the selected `file_sha256` as optional `_target_sha256` with Open to reject a destination changed since selection. The server validates the target document, pending transaction and undo history before changing the active project.

Successful actions return `{ok:true, id, name, context, warning?}`. The returned `id` is the active storage identity; confirm it against a fresh state read before adopting that document. An event or broadcast failure after activation returns a warning, not a failed Open. Save As copies folder/history files and keeps their media references; Duplicate copies the saved edit with fresh proposal/history state. Use portable packages for independent resource ownership. A completed copy whose activation fails is retained and its path reported.

Save As and Sample share one admitted preparation worker. `project_action_busy` in `/api/project/state` reports whether that worker can still finish an action. After a lost or malformed reply, inspect state and the catalog without replaying the action; wait until preparation is no longer busy before reconciling. The browser's Refresh editor performs this observation. There is no durable lifecycle-command receipt or automatic retry guarantee. Synchronous OS calls have no hard cancellation deadline, and publishing a folder is not one atomic multi-file transaction.

Only when the active project JSON is invalid, Open can instead receive `_recovery_origin:{workspace,project,current_sha256}` from a fresh active-project recovery inspection. All three fields must still match, and the current project must still be invalid. This permits leaving damaged bytes intact while opening a validated destination; it is not a general context bypass. Project IDs are contained, unlinked library folders, and lifecycle source/target JSON is limited to 32 MiB.

## Project recovery (unreleased source)

`GET /api/projects/recovery` inspects the active project's saved versions without loading or replacing its current JSON. It returns `project` (the storage ID), `workspace`, `origin_context`, `current_sha256`, `current_valid`, `current_error`, `candidates`, and `unavailable`. Each candidate includes an opaque `id`, `sha256`, `name`, `kind`, `saved_at`, `sequences`, `clips`, and `media` count. Unreadable versions are reported separately.

`POST /api/projects/recovery` restores a deliberately selected version. Supply `project`, `candidate`, `sha256`, and `current_sha256` from the inspection result. An optional `editor_project` preserves an open editor copy as recovery evidence; it is not automatically restored. The selected project and both fingerprints must still match. For an inactive target, inspect `GET /api/projects/recovery?project=<storage-id>` and send its `origin_context` as `_context` with the restore request. The active source context must still match even if another action has since selected the target. Restoring an inactive project does not switch the editor; opening it is a separate guarded action. Supply `editor_project` only when that editor copy belongs to the target project. A mismatch returns HTTP 409. Invalid recovery content returns HTTP 422; preservation or filesystem failure is reported without claiming success.

Before replacing the project, the operation preserves and verifies current/pending/editor bytes, undo history and any existing transaction journal under the project's `recovery/` directory. It then rechecks project/history/journal bytes before publishing a prepared restore journal. The selected project and empty undo stack commit as a pair. Exceptions or process interruption before the commit marker roll back both; a committed restore retains both. Version-2 restore journals embed a checksummed copy of the superseded journal, including malformed bytes. Rollback reinstates that journal and requests Recovery before exposing its possibly inconsistent files; successful commit retires it. Version-1 edit journals remain supported. Unknown current bytes stop automatic rollback.

A successful result includes `ok`, `name`, `preserved`, and `selected_sha256`. An optional `warning` reports cleanup or audit-history failures after the committed restoration; these do not mean the restore should be replayed. A 409 conflict during preservation occurs before publication. Preserved readable copies appear in later inspection results. Automatic rollback is tested against real process exits on Linux; power-cut durability, multiple server processes and native Windows behavior remain unverified. Browser drafts are restored only by explicit selection.


## Guarded project edits (unreleased source)

`GET /api/project/state` returns `{project: <document>, context: {workspace, project, revision}, project_action_busy: <boolean>}`. The original `GET /api/project` still returns the plain document. `context.project` is the storage folder ID; it can differ from the document's `id`, including after Save As. Treat all context fields as opaque.

For `PATCH /api/project`, include `_context` alongside `ops`. For a full `PUT /api/project`, include it alongside the document fields; `_context`, `_actor`, `_source`, and `_client` are removed before writing the document. `POST /api/undo` and `/api/redo` also accept `_context`. The comparison and mutation run under the same store lock. A changed workspace/project/revision returns HTTP 409 with `detail.code: "project_changed"`; the request has not edited the current project. A supplied malformed context is also rejected. Omitting context preserves legacy behavior.

Successful PATCH/PUT responses include the new `context`. Send dependent writes sequentially with the last acknowledged context. Undo/redo clients should fetch `/api/project/state` after success. A revision is based on the complete saved document, including legacy/other-route changes. An optional response `warning` reports history or snapshot issues after a committed save. Do not replay an insert after a lost response: re-read, inspect, and reconcile the intended change. There is no idempotency/retry token.

To restore a deliberately selected browser draft using `POST /api/projects/recovery`, supply `project`, `workspace`, `current_sha256` from the recovery inspection and `draft_project` containing the full selected document. `editor_project` can additionally preserve the currently open editor. The server validates and stages the draft as a verified recovery candidate, archives current/pending/editor/undo copies, then restores it. Wrong workspace or stale current content returns 409 before staging. The `current` candidate lets the human retain the saved document while preserving an unsaved editor copy in history. General legacy mutation routes do not yet implement the optional `_context` contract.

## Guarded proposal decisions and undo

Read `GET /api/project/state` once when preparing an edit. Include its `context` as `_context` with PATCH/PUT, proposal creation, preview creation, proposal decisions, undo or redo. A supplied stale or malformed context is rejected with 409 before any commit; missing context retains the legacy contract and does not prevent a delayed request from following the active project. Storage identity differs from the project JSON's `id`.

```python
state = cr.project_state()
# Build operations using state["project"], keeping this same read context.
cr.propose("Tighten the opening", items, context=state["context"])
# Direct edits can also opt in: cr.patch(ops, context=state["context"])
```

The example agent's refinement proposal uses this captured-read contract. Its rough-cut and remaining legacy recipe helpers retain their historical API behavior; this is not a claim that every SDK workflow is guarded.

Proposal creation checks each item's result against the captured project. Decisions revalidate against the current project and apply the same overlap normalization as core edits. Operations cannot modify proposal control records. Only `accept` and `reject` are valid decisions, and already-decided items produce 409. A batch applies in the submitted item order, commits once, and produces one undo step; any invalid item prevents the entire batch. The browser uses batches for both single and bulk decisions, waiting for its core save queue first.

The single-item response retains the item fields and adds `ok`, `context`, `warnings` and `warning`. The batch response returns those fields plus `items`. Event/training append failures are secondary: a response with `ok:true` and `warning` means the project/history commit succeeded; do not replay it. New batch WebSocket events identify `project`, `proposal`, `items`, `decision`, `client` and `context`; consumers should refresh project state. Undo/redo now emit `project_replaced` events because their exact changes can include whole containers or a full project replacement.

New undo entries preserve exact changed values and object identities, including normalization and removed/null fields. Unexpected edits to those values produce a history conflict without consuming the entry. Existing operation entries still load and are upgraded after successful use; lost information in an old entry cannot be reconstructed. These guarantees cover the guarded core commit paths, not every specialized mutation endpoint. Project/history journals handle process interruption within one server's writer coordination. Backend startup now blocks another cooperating process from owning that data folder; native Windows ownership/file-sharing/durability and live UI acceptance still need verification.

### Prepared frame review

`POST /api/proposals/{pid}/preview` takes `{items:["item-id", ...], _context: state.context}`. Items are applied in the submitted order and normalized once with the same builder used for direct acceptance. The read-only result contains `ok`, `id`, `proposal`, `items`, `plan` (SHA-256 of the prepared edit excluding decision records/save time), `context`, `expires_at` (Unix seconds), `warnings`, `changes` (exact before/after paths), and `sequences:[{id,name,fps,duration}]`. Schema migration happens before capture. Creating a preview does not save the project, write history, decide items or append training records.

Fetch `GET /api/proposals/preview/{id}/frame?sequence=<id>&t=<seconds>` for a PNG using the prepared project's media, sequences and effects. It uses the production FFmpeg frame renderer, checks finite time/bounds, and returns `Cache-Control: no-store`. At most two frame requests run at once (429 if busy). Scratch belongs to the request and is retired after its consumers exit. A changed project, released/expired preview or canceled render yields 409; render failures and invalid bounds yield 422. Select another frame only after/coalesced with the outstanding request to avoid wasted work.

Accept the reviewed selection through the existing batch route, adding `_preview:{id: view.id, plan: view.plan}`. The proposal, exact ordered item IDs and current saved context must still match the captured view. Passing a newly read `_context` does not rebase an old view. The server commits the prepared project, marks those decisions and writes one undo entry. A successful acceptance retires its snapshot; failures before commit retain it until release/expiry. Legacy/direct decisions without `_preview` keep their existing behavior.

`DELETE /api/proposals/preview/{id}` releases the view and signals cancellation to its attached frame renders. The response is `{ok: boolean}` and release is idempotent. Views expire after ten minutes, are bounded to eight per server (429 when full), and are lost at restart. They snapshot project JSON rather than referenced file bytes; external changes to media, fonts or LUTs are outside this revision guard. The browser's review is a silent frame viewer, not a video/audio render job.

Rendered previews use the main renderer, not draft-segment stitching. Pass the context from the same `project_state()` read used to choose the sequence. Reuse one `request_id` (8–80 letters, numbers or hyphens) when retrying an uncertain creation request; the running server queues it once and rejects reuse for a different edit. Job and request metadata are in memory, so restart ends that deduplication/rediscovery scope. Source bytes are checked at capture and validation, not frozen during playback. Existing calls without these optional fields remain accepted. The SDK supports `render_preview(seq_id, context=context, in_out=True, request_id=request_id)`.


### Render coverage window

`GET /api/render/segments?sequence=<id>&start=<seconds>&end=<seconds>` optionally limits cache inspection to segments intersecting the requested half-open window. Supply both finite bounds, with `start >= 0` and `end > start`; otherwise the route returns 422. Omitting both preserves the full-sequence response. Results include `window: [start, end]` (or `null`), saved `context`, `sequence`, `segments`, and a separately validated `ready_preview`. Segment boundaries are retained rather than clipped to the window. Coverage is advisory; enabling playback must still use the preview validation endpoint. The server checks saved context again after filesystem inspection.

### Overlap normalization and overwrite ordering

Generic edit batches normalize unlocked tracks by original list order: later entries win overlapping time. `set_clip` updates an existing clip in place and does not raise its priority. To intentionally move a clip over later entries, remove and reinsert its full object at the desired end of the track list within the same saved-context batch; preserve relative order for multi-clip moves. Native drag now does this for ordinary same-track overwrite moves. Do not issue removal and reinsertion as separate saves.

Normalization prepares all fragments before publication and preserves source/automation/fade timing. Locked tracks are untouched. Picture-transition interiors, invalid curves/timing and constant/ramp speeds below 0.000001 reject; output/input clip count is bounded at 100,000, copied curve points at one million and estimated duplicated clip payload at 32 MiB. A rejected batch must be corrected/reviewed against its captured project context rather than blindly retried. Ctrl insertion is separate from this overwrite policy. Keyboard nudges use the same remove/reinsert ordering as ordinary drag moves.

### Source trim restoration metadata

Native mouse and keyboard source edits submit complete planned clip payloads. Preserve `source_edit_window` extension data when round-tripping clips. Version 1 records original speed-ramp/duck points and their cumulative clip-local offset; the editor uses a record only when its derived visible curve matches the current curve. Splits and overlap slices advance that offset, while ordinary partial `set_clip` curve changes immediately invalidate only the affected history category. Full source plans supply updated history explicitly; generic JSON-pointer curve edits must clear the affected restoration record themselves. Ordinary keyframe and marker times may be outside the visible clip; those anchors preserve extension behavior. Do not clamp or discard them merely because they are not visible.

`audio.fade_window.offset` may be negative or exceed its original duration after extension. The envelope stays on its original clock while its fade-setting signature matches; changing fade settings reanchors both fades to current clip edges. Held clips encode timeline duration as `out-in_`; for non-image media the frozen `in_` must be before media end, but `out` can exceed it. Legacy scalar source-field patches do not automatically provide the shared trim planner's preservation contract.

### Planned range editing (unreleased source)

The editor uses `frontend/timeline-range.js` to plan `planInsert(sequence, trackIds, at, duration, hooks)`, `planRemove(sequence, trackIds, intervals, {close}, hooks)` and `planOverwrite(sequence, placements, hooks)`. A placement is `{trackId, clip}`; hooks supply the actual `{duration, sourceOffset, speedAt}` clock for each clip, a fresh-ID allocator and reserved project IDs. These are browser/pure planning functions, not new HTTP routes. Never replace their retime clock with `(out-in_)/speed` for ramped or held material. The planner returns an independent candidate sequence and changed tracks; it does not publish or implicitly shift sequence annotations. Input/output clip counts, copied payload, work, placement and range counts are bounded; a refusal must leave the original unchanged.

The frontend compares the complete candidate against the original saved sequence, submits full changed clip arrays and any annotation fields in **one** existing saved-context `PATCH /api/project` batch, and records one Undo step. Keep the same captured project/context for every path index; do not submit clip and annotation changes separately. Generic operations still pass backend validation and overlap normalization. Preserve source-edit history, signed fade clocks, easing/handles and surviving marker ownership from the plan. A partial unsupported picture transition rejects atomically, including when it occurs on a later participant.

Scope belongs to the caller: Lift/Extract uses all unlocked tracks regardless of targeting or sync lock. Insert uses explicit destinations plus other unlocked sync-locked tracks. Selected ripple deletion and gap close use selected/gap tracks plus those same peers, even if an explicit track has sync lock disabled; normalize selected spans to a disjoint union once and reject any unselected participating clip intersecting it. Extract intentionally removes crossing material. Ordinary Delete, Lift and overwrite do not close timeline time. Explicitly selected locked tracks reject the complete selected deletion.

`frontend/timeline-annotations.js` independently maps sequence markers, captions and In/Out for insert or closing removal. Insert splits crossing captions with unchanged text and fresh IDs; removal retains only surviving pieces. Point markers within removal clamp to the join, duration endpoints compress, and collapsed In/Out clears both fields. Insert Out is exclusive. Lift/overwrite leave sequence annotations unchanged. Transcripts are retained with existing timing-freshness checks. Clipboard copies keep original destination track IDs/kinds, preserve relative offsets and remap clip/group/internal-link IDs; ambiguous or changed media and foreign nested sources reject instead of silently rebinding. These client policies are not automatically inferred by arbitrary agent patches.

Native acceptance remains unverified under RE01–RE14. Managed Remove Silences now uses the separate server-authoritative analysis contract below; generic patches do not automatically acquire its policy. Retiming audio, effect histories and generated/nested animation clocks require their separate acceptance gates.

### Managed source analysis and reviewed application (unreleased source)

`POST /api/media/scenes` and `POST /api/audio/silences` require a current saved `_context` and queue `kind: "analysis"` tasks. Supply `media_id`, logical `in`/`out` and settings; supply both `sequence` and `clip_id` for a timeline target, whose range must be the complete captured `in_`/`out`. The response contains `{ok, task, context, message}`, not immediate cuts/gaps. Use a stable `request_id` to reconcile a queue request instead of replaying an uncertain outcome. Starting/completing/reviewing analysis does not mutate the project. The existing task catalog/cancel/retry routes expose ownership, resource wait and durable state.

`POST /api/tasks/{id}/analysis` with a fresh `_context` reviews a ready result. The response contains `{ok, task, context, result, plan?}`. A later revision of the same project is permitted only while captured source metadata/file stamps and the complete target clip/track remain valid; unrelated edits do not require another FFmpeg scan. A changed target/source/file or foreign project rejects. The result is version 1, `kind: "scenes"` or `"silences"`, `clock: "media"`, with `media_id`, target IDs, `range: {start,end}` and `cuts: [time,...]` or `silences: [{start,end},...]`. A timeline review returns `plan: {ops, summary, fingerprint}`. The summary exposes timeline `cuts` or `ranges`, removed duration and affected tracks. Submit the returned context and fingerprint to `POST /api/tasks/{id}/apply`; do not alter or apply returned ops independently. The server recomputes its canonical plan, checks the reviewed context/fingerprint and commits clips, sequence annotations and its application receipt in one history transaction. Managed Remix extends this analysis contract as described below; generic replacement-source routes, beats, sync and recipes retain separate contracts.

Supported analysis uses original file-backed video/audio and the common signed timestamp origin. Subclip/interpretation conversion applies once; incompatible/nested subclip chains, synthetic sources, stills/image sequences, missing streams and invalid bounds are refused. Scene threshold is 0–1 (default 0.35). Silence threshold is -120–0 dB (default -38), relative to the loudest measured RMS window, not absolute dBFS; native windows are 20 ms, retaining channels without mono cancellation. `min_gap` is 0–60 logical seconds (default 0.45); `pad` is 0–10 logical seconds (default 0.08) around speech edges. Wholly silent sources remain valid. Logical and native windows each have a one-hour maximum; results are capped at 10,000, output/logs and copied plans are bounded, and the worker has a timeout. Source checks use metadata/stat identity rather than full file hashes.

Canonical source inversion supports constant speed, reverse and ramps; held clips refuse. Scene cuts align to sequence frames and affect only the analyzed video clip. Silence removal rounds inward on the picture grid when picture tracks participate, closes the normalized union once and includes the explicit target plus other unlocked sync-locked tracks. It rejects unselected participating clips crossing removed time and locked targets. Captions/markers/In–Out follow the closing-removal mapping described above. Full surviving source, curves, fades, markers and valid restoration history are preserved; unsupported partial picture transitions and bounded-plan failures reject atomically. The existing variable-speed audio renderer remains independently unqualified.

SDK methods are `start_analysis(kind, media_id, *, context=None, sequence=None, clip_id=None, in_=0, out=None, request_id=None, **settings)`, `wait_analysis(task_id, timeout=900, poll=.5, *, context=None)`, `analysis_result(task_id, *, context=None)` and `apply_analysis(task_id, reviewed)`. `wait_analysis` timeout leaves the task inspectable. `scenes(...)` returns the reviewed absolute media cut list; `silences(...)` returns the source result. `remove_silences(clip_id, ..., preview=True)` returns the review; by default it waits and applies the canonical plan. Continue to honor existing actor/client, collaboration and proposal policies. Native UI/HTTP/SDK acceptance is AN01–AN10.

### Detached audio and source-match ownership (unreleased source)
