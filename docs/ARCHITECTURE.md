# Architecture and roadmap to Premiere-class capability

## Now (v0.9)
Browser UI (vanilla JS, no build step) ↔ FastAPI local server ↔ FFmpeg. State = one JSON project; UI and agent both edit it through the same op API; the event log is the audit trail and the training source. Preview = a canvas compositor over a pool of video elements (all tracks, transforms, opacity, transitions, color approximation, titles, captions); render = FFmpeg filter graph (exact), with keyframe expressions, six transition types, color filters, burned captions, In/Out range. Runs on the workstation; nothing leaves the machine.

## What "comparable to Premiere" requires, in build order
1. **Editing depth (weeks 1–3)** — done in v0.2: ripple/roll/slip/slide, multi-select, group and cross-track moves, add-edit, ripple-trim to playhead, linked audio, tracks add/solo/height, sequence In/Out, keyframes (linear), speed dialog, autosave/restore. Remaining: multiple selection and group moves; slip/slide/roll/ripple trims with the `Y`/`U`/`N`/`B` conventions; track add/remove/height; linked audio/video selection with unlink; nested sequences; clip speed ramps; keyframes on transform/opacity/volume (bezier); markers with notes; in/out on the sequence with "export in-to-out"; project bins and search; proxy generation (WebM/H.264 low-res) so every browser previews smoothly.
2. **Real preview (weeks 3–6)**: a WebCodecs/WebGL compositor in the browser that mixes tracks, transitions, transforms and titles in real time (the current switcher becomes a fallback) — or server-side segment pre-rendering for scrub accuracy; audio graph via Web Audio (multi-track mixing, level meters, ducking preview).
2b. **Done in v0.3**: nested sequences (pre-rendered for export, recursive compositor for preview), adjustment layers, masks with feather (PNG alphamerge fast path), eased/hold keyframes with a draggable lane, audio effects, stills, bins/search, multi-output export with center-crop/pad, hardware encoder selection, FCP7 XML import, editable shortcuts, exact-frame preview, direct manipulation in the monitor, resizable panels.
2c. **Done in v0.4**: fontconfig fonts and full text styling, graphics templates (layered box/text), gain rubber-band, constant-power audio transitions, auto-duck, clip enable/disable, lift/extract, copy/paste/paste-attributes, match frame, nudge, selection handles in the monitor, render QA (ebur128), auto-captions hook (whisper), offline media + relink, loudnorm inside the graph.
2d. **Done in v0.5**: time remapping (exact inverse-integral setpts), rate stretch + pen tools, frame hold, blend modes (pre-composed canvas + blend + alpha-preserving overlay), animated masks (quarter-res geq matte), bezier keyframes baked to linear sub-keys for the render with a value-graph editor in the UI, context menu + labels, gap close, extend edit, history panel, workspaces.
2e. **Done in v0.6**: Premiere-mirroring workspace (menu bar, header bar with Import/Edit/Export and workspaces, Source dock with Effect Controls + Audio Clip Mixer, Program transport with Lift/Extract/Export Frame/safe margins, Project list/icon views with columns and bins, Effects panel, Info panel, Premiere-style track headers with source patching, lock, sync lock, output toggle), Type tool, sync-locked insert/ripple with clip splitting, one-click cross-platform launchers with FFmpeg bootstrap.
2f. **Done in v0.7**: Media Browser, subclips, clip markers, caption track, shape/zoom/track-back tools, edit-point selection + keyboard trims, crop/blur/sharpen/vignette/chroma key/anchor/curves/pan, auto-match loudness, proposal ghosts + agent glow, reason taxonomy, playback telemetry, brief, session summary, training export.
2g. **Done in v0.8**: multicam (source sequences, multi-camera view, cut-and-switch), multiple projects with collect, scene edit detection, text-based editing from word-level transcripts, reverse/optical-flow/frame-blending, per-segment audio tempo with pitch preservation, track buses + master chain, color wheels/vibrance/per-channel curves, scopes, more transitions, export formats and presets, groups, fit modes, marker types/durations, dock tab moves, preferences.
2h. **Done in v0.9**: effect registry (73 effects, generated controls, drag-to-apply, live preview hints), Warp Stabilizer, drop shadow, 14 more transitions, bundled LUTs/templates/presets, SVG icon set, User Guide + Feature Matrix, API smoke test.
3. **Effects and color (weeks 4–8)**: a Lumetri-style color panel (exposure/contrast/highlights/shadows/whites/blacks, temperature/tint, saturation, curves, LUT import) mapped to FFmpeg `eq`/`curves`/`lut3d`/`colorbalance`; blur/sharpen; crop; masks (rectangular/elliptical) via alpha; a transitions set (dip to black/white, wipes, push) via `xfade`; audio effects (EQ, compressor, de-noise, loudness match) via FFmpeg audio filters; captions track (SRT import/export, burn-in styling) and a titler with fonts/alignment/shadows.
4. **Media and performance (weeks 6–10)**: hardware-accelerated encodes (NVENC/VideoToolbox/QSV), background proxy pipeline, frame-accurate scrubbing via server-side frame service, waveform zoom levels, media relinking, import of image sequences and audio-only files, PSD/PNG with alpha.
5. **Interchange (ongoing)**: OpenTimelineIO export/import; FCP7 XML export so a sequence can be opened in Premiere or Resolve when needed; EDL/CSV of cuts for the agent's reports.
6. **Agent-native features (unique)**: "explain this cut" (the agent annotates why each edit exists); "review pass" where the agent's proposed changes appear as pending ops the human accepts/rejects one by one (each decision logged); automatic QA (spec/safe-zone/loudness/caption timing) on every render via the package scripts; A/B variant sequences with shared media; retention-curve import from platforms to align cuts with drop-offs.
7. **Polish**: workspace layouts, panel docking/resizing, keyboard map editor, dark/light, multi-monitor, autosave/versioning, crash recovery.

## Choices and why
- Web UI so the agent can drive it headlessly with Playwright when useful and so no native toolkit is needed; FFmpeg as the render engine because it is deterministic, scriptable and already the package's toolchain.
- JSON over a binary project: diffable, agent-readable, and versionable in git.
- Ops (not full saves) as the edit primitive: they *are* the training data.
- No cloud: media and edit logs stay on the workstation.

## Not goals
Reproducing Adobe's icons, assets or code; multicam broadcast workflows; 3D/VR; a plugin ecosystem (until the core is solid).
