# Guided editing in Filmocity

Open **Workflow** in the top toolbar, **Window → Guided editing workflow**, or command search. The six steps use the current project and sequence. You can move between them without marking anything complete. The counts describe actual clips, words and captions; exporting is complete only when the Render Queue reports success.

1. **Footage:** import one or more files, select library items in story order, adjust their order, name the rough cut and choose its aspect ratio/frame rate. Build creates a new sequence and preserves existing timelines. Files are copied under unique names in the project workspace. A failed batch does not leave a partial library import. Copies may be retained after an uncertain disk commit for recovery; undo removes library entries, not the copied files.
2. **Story:** queue local transcription, then open **Tasks → Apply transcript** when it is ready. Keep editing during analysis; changes to its target dialogue/source require a new transcription. Search the transcript and choose passages or individual words to keep. Thirty passages appear per page; search and the low-confidence filter cover the full transcript. **Words…** opens individual selection and text correction; Shift-click spans a range. **Save word corrections** changes wording without retiming or altering the source audio, in one undo step. Playback stops at the word/passage end. Creating a cut preserves the original sequence and rebases retained words, clips, keyframes and markers. Captions are regenerated later. Constant-speed cuts are supported; ramps, reversed clips, holds and multicam flags are rejected. Breathing room defaults to 80 ms (adjustable 0–500 ms), bounded by excluded neighboring words. Ambiguous overlapping speech must be kept together or trimmed manually. Review edit points by ear.
3. **Sound:** explicitly choose dialogue clips and apply rumble removal, optional noise reduction and compression. Controls remain ordinary editable clip effects. Reapplying replaces only the filters added by this workflow. Other clip and track effects remain. This is a filter recipe, not voice isolation or a measured loudness target. Listen to the rendered preview, especially before turning up noise reduction.
4. **Captions:** create short captions and choose clean, boxed or word-highlight styling. Untouched captions generated here follow later saved word corrections. Manually edited or legacy captions stay intact and are flagged for review when affected; open the captions editor and acknowledge the review explicitly. Regenerating replaces existing captions in one undo step. Review readability, wrapping, names and punctuation in a rendered preview. SRT download is available in Deliver.
5. **Versions:** create portrait, square or landscape outputs. Each has an independent copy of its content, including nested sequence dependencies, and a caption layer sized for the output. Fit preserves the full picture with letterboxing; Fill uses a center crop. Open the version’s content sequence to adjust edits or effects. Changes to the original edit do not automatically synchronize these copies. Shared original media files remain shared, so replacing those files affects all versions. Inspect faces, titles and safe areas; automatic subject tracking is not included.
6. **Deliver:** render the full sequence for review, open the existing Export dialog, then follow the job in the Render Queue. Its completed result provides the exact output/review links. Each version is exported separately in this first milestone.

## Background tasks

Open **Tasks** in the toolbar or **Window → Background tasks**. Imports queue thumbnail, filmstrip, waveform and proxy preparation automatically. Two preparation/analysis workers run at once and only one loads a speech model. Exports remain in Render Queue; **View exports** opens it.

A speech task moves from Queued through Preparing audio, Loading speech model and Transcribing to **Ready to apply**. Work without a reliable percentage shows an indeterminate bar. Keep editing while it runs. **Open sequence**, then **Apply transcript**, saves one undoable edit; existing captions remain available and may need review. Save or discard word-correction drafts first. If the target/source changed, download the JSON result for reference or start a fresh transcription. Ready results never replace words automatically.

Cancel waits for the current operation to stop. FFmpeg processes are cancelled and reaped; model loading or an in-process speech step can take longer to return. A short publication/apply already in progress must finish before cancellation can take effect. Failed/cancelled/interrupted jobs offer **Retry**, which revalidates inputs; changed inputs require a new task. If admission failed before a task existed, use **Retry preparation** beside the media item. Imported originals are retained.

Reopening the same data folder keeps ready results and marks unfinished work interrupted. Nothing restarts automatically. Corrupt/unwritable history shows a warning; keep the result download if available. Task receipts are history, not a backup of source-media bytes. The panel displays 30 tasks per page and recent terminal history; disk history currently has no cleanup control.

The older **Captions** panel now searches/pages captions 30 at a time. **Open transcript editor** takes you to Story, and **Generate captions in Workflow** retains the explicit replacement step.

## Speech setup

Use **Speech tools / System Check → Install auto-captions** if the optional speech engine is missing. The first use downloads the selected model; subsequent analysis runs locally. Base is the initial selection. Recognition quality, model download and representative Windows performance still need native validation. A packaged executable cannot install speech tools in place: use source mode with `launcher/bootstrap.py install --with-whisper`. A speech-enabled native bundle requires its own dependency packaging and acceptance; the default candidate does not establish that support. The Linux tests substitute deterministic speech results; they do not claim model accuracy.

Transcription currently occupies the workflow action until it finishes. Keep the app open. There is no background speech-job queue, diarization, translation, automatic filler-word removal or cancellation button in this milestone.

## Saving and recovery

Workflow actions wait for pending editor saves and capture the current project version. Background transcription saves a separate result. Apply requires the original project and unchanged target/source; unrelated sequences, captions and completed previews can change. Earlier synchronous API callers still revalidate the whole project revision before committing. If a saved timeline changes, refresh the workflow and review the choices before applying; refreshing clears its draft choices. Thumbnail/proxy completion can refresh the version without discarding those choices. Old transcript timings are rejected after timeline timing changes detected by the workflow. Legacy transcripts without a recorded timing basis cannot establish their freshness; transcribe again before relying on them.

Each completed project mutation uses one undoable project/history transaction. Import preview updates preserve the matching import receipt so undo and redo still work after thumbnails complete. If the server reply is lost, the editor preserves its draft and requests Recovery instead of automatically repeating a possibly completed action. Source media bytes are not snapshotted by transcription or version creation.

Word corrections are separate from passage selection. Up to 500 pending corrections are stored as a small browser draft while typing; they do not rewrite the project until saved. **Recover or download word corrections** offers explicit recovery when project revision, sequence and original word timings still match. Older drafts remain downloadable for manual review. Different editor windows keep separate copies. A failed save retains corrections; other workflow mutations ask you to save or discard them first.

Browser drafts stay in that browser/profile and address. They are not cloud backups and do not automatically follow a changed port, device or native profile. If storage fails, corrections remain in memory while the window stays open and can be downloaded. Download before closing in that case. Draft recovery preserves word corrections; passage selections and other form choices are session state. Editing wording does not remove fillers automatically or generate replacement speech.

## Validation boundary

The retained Linux checks cover workflow builders, word/caption corrections, real project/history files, controlled route/DOM adapters, stale replies, draft recovery, safe import and real FFmpeg picture/audio output. They do not establish live HTTP, full browser interaction, WebView2/native Windows acceptance or speech-model performance. See [Windows acceptance](WINDOWS-TEST-HANDOFF.md), the [comprehensive QA matrix](WINDOWS-QA-MATRIX.md) and current evidence (archived evidence: `../benchmarks/background-tasks/validation.json`).
