## What changed

### v0.46.4 source: owned render contexts

This source implementation does not alone establish an installed release. Exact package/API/native acceptance for these bytes is recorded separately in the retained local October 3 render-scope evidence. `backend/render_context.py` supplies a lazy per-operation scratch directory with exclusive helper filenames, explicit consumer leases and visible retirement failures. Text, shapes, masks, sendcmd files, chapters, nested MP4s and incremental concatenation/audio helpers now belong to that context. Render, frame and CLI entry points create and retire their own contexts; an explicit `context=` borrows the caller's scope. Encoder supervision waits for the process, stderr drainer and stall watcher before releasing its lease. A retirement denial raises `RenderCleanupError`, records `scratch_retirement` with the retained path, and leaves explicit cleanup retry possible. A queue job reports that error and still retires its holder/task; a successor continues. Publication can already have completed before scratch retirement fails, so an error may coexist with a completed output. That distinction is retained in diagnostics.

Nested and multicam sequences retain the existing rendering graph. They use the parent cancellation holder, progress reporting, bounded stderr and stall supervisor. A nested result is reusable only from a completed successful record in the same context; existence of a pathname never admits an incomplete nested encode. Helpers are written and closed before command use, with unique paths even for identical inputs. Generated paths do not rewrite the original project JSON or replace original source provenance. Segment caches remain persistent and opt-in; segment stages stay beside their cache destination for Windows replacement. Single-file and PNG publication remain staged. The existing bounded Windows project-save behavior is unchanged.

Cancellation is available during queue admission-to-running transitions and building even when no encoder is present. Full/frame/incremental commits serialize with cancellation using the same publication lock as PNG exports; cancellation after commit is refused. Async Render and Replace, cover and transcription requests signal and join their actual rendering thread when the coroutine is cancelled. Caption/transcript WAVs stay private through the lazy transcription readers. This does not make a blocking filesystem hash or transcriber call immediately interruptible.

Python command inspection returns `(RenderCommand, graph)`, with list-compatible argv. Without `context=`, the returned command owns its scope: retain the command and use `with command:` around execution, or call `command.close()` after every external process using it has exited. A supervised `_run_ffmpeg(command)` automatically borrows its context. With `context=`, the caller retires that scope; closing a borrowed command does not retire it. Direct generated-file helpers require `context=`. Slicing, concatenation and `command.copy()` retain the owner. Converting argv to a plain list or JSON strips its lifetime owner, so retain the command/context separately. Garbage collection offers only best-effort cleanup for legacy callers and logs failed retirement; it is not the supported ownership protocol.

`GET /api/render_command` preserves `cmd` and `graph` and adds `cwd`, `scope.id` and a `scope.release` URL. Execute serialized argv with `cwd=response['cwd']`: captured Windows fonts use ASCII aliases in that owned directory. A null `cwd` means the usual inherited working directory. The server retains those files until explicit `DELETE /api/render_command/{scope}`. Call release only after external command consumers have exited: the server cannot observe an encoder launched by another process from serialized argv. There is no timed deletion of a usable returned command. Cleanup failure returns HTTP 500 and retains the scope for retry. At most eight live/building command scopes are admitted; capacity reservations cover concurrent builders and excess inspections refuse with HTTP 429. Explicit release permits new admission. Failed retirement keeps its slot until an explicit successful retry; diagnostic messages are capped at 500 characters and the last eight records. Retention is in memory and has no crash recovery or persistence guarantee.

Source validation passed 31 new context/lifecycle cases, the existing 89 reliability regressions (32 PNG publication, 12 queue retirement, four Windows save, 28 resource/relink and 13 export safety), and the existing 122 catalog render cases (26 transitions, 43 video effects, 15 layer animations, eight generators and 30 audio effects). No skips were accepted. Real bundled FFmpeg covers nested success/failure/cancellation/stall, multicam and deeper nesting, frame/CLI output, incremental reuse, concurrent command execution and successor queue execution. Failure injection covers partial nested files, helper/build failure, drainer-thread startup failure and cleanup denial/retry. Transcription lifetime uses a controlled lazy reader with the real audio encoder; installed speech-model fidelity is not established.

Logs, summaries, fixtures and rejected attempts are retained under `.render-context-evidence/`, `.render-context-tests/` and the existing owned PNG/queue/save fixture folders. The worker left existing test files unchanged and used a fixture-only `_TMP` sentinel for the old PNG suite. The parent then removed that obsolete import/cleanup fixture, retaining every publication assertion, and ran the actual renderer with no `_TMP` sentinel. Parent validation passed 124 Python tests (31 context lifecycle, four command-scope admission/retry, and the existing 89 regressions), with no skips, plus route guards. The final reviewed renderer matched the released baseline on all 145 decoded RGB frames and six decoded PCM streams across graphics, masks, sendcmd transitions, nested/multicam, incremental and still-frame cases; chapter metadata and original JSON also matched. These are technical fidelity checks, not normal-speed watching, listening or taste approval. Rejected scratch from the early path-length failures was frozen under `.render-context-evidence/rejected-scratch-bytes/` before explicit retirement. The first attempts exposed a fixture duration spelling/setup error and Windows path-length failures; those logs remain failed evidence. Temporary basenames were shortened without changing output filenames or the cache-key scheme.

Exact rebuilt package/API checks and native cancellation/progress/shutdown review are separate release gates recorded with executable hashes in the current work directory. The wider nested/matte/format/color/audio fidelity matrix and large-project performance remain unestablished by this batch. Sources, fonts, LUTs, stabilization files and persistent caches still read live bytes. Complete immutable source-byte capture is the next required foundation. This adds no source snapshot, durable job queue, restart recovery, crash-safe scratch sweeper, owner taste approval, delivery authority or Adobe parity claim.

### v0.46.3: queue retirement and audit failures

The reviewed queue implementation is integrated in the current source; exact installed acceptance is recorded by the release manifest. The retained local October 3 queue-cleanup failure probe reproduced an event-store exception escaping the released worker after a completed render, leaving one render holder and one unfinished queue task. The new regression also failed on the unchanged candidate: its first event append escaped, the first holder remained, and the second job stayed queued (two unfinished tasks, zero acknowledgments). The red transcript and per-case state are retained under `.render-queue-lifecycle-tests/` in this candidate.

Every acquired queue entry now has one retirement path in `finally`: event recording is attempted independently, then the holder is removed and `Queue.task_done()` is called exactly once. The path covers completed renders, render/resource failures, queued cancellation, missing job records and failures in job or command-log bookkeeping. Queued cancellations receive a terminal event attempt as well. A failed audit append or event serialization no longer changes a completed job to a render error, overwrites an encoder/cancellation error, or prevents the next job from running.

Jobs expose `event_persistence.status` as `recorded` or `error`. Failure adds a diagnostic with phase `event_persistence` and a visible `qa.flags` warning that the audit record is not confirmed. Error detail is limited to 500 characters; diagnostics retain at most eight entries. Existing output links, PNG manifest/frame hashes, QA measurements and flags remain intact, and a verification-error status remains an error. `recorded` means the event append returned, not a durable transaction or fsync guarantee. Diagnostics remain in memory; a failed append is not retried and may have left a partial record. There is no queue persistence or restart recovery in this change.

Focused validation uses the production `start_render`, `_render_worker`, resource preflight and cancel route with a bounded in-process queue. Twelve lifecycle tests cover a real event-file open failure followed by a successfully persisted second job, event serialization failure, render failure, a source disappearing after enqueue, enqueue rejection, queued cancellation, job-start/command-log bookkeeping failures, missing job retirement, preservation of verification errors, and PNG publication/validation cancellation combined with audit failure. The queue observes acknowledgment counts while calling the real `Queue.task_done`; retirement is never stubbed. Per-run job state, outputs, source hash and red/green transcripts are retained under `.render-queue-lifecycle-tests/`.

The candidate also passed the existing 32 PNG publication regressions using the existing FFmpeg/ffprobe binaries, including real-media failures and cancellation, and all four Windows save-sharing tests including an actual reader sharing denial. These checks had no skips. Those dated tests used their captured Python environment and exact FFmpeg/ffprobe tools on PATH. `TEMP`, `TMP` and `FILMOCITY_ROOT` stay inside this candidate, and fixtures inherit owned parent ACLs. Existing test sources and assertions are unchanged.

Parent verification passed 89 focused Python tests, including the existing resource/export and Windows-save suites, with no skips. An isolated compiled-source desktop candidate completed two real FFmpeg PNG jobs through an event-file failure; all 24 published frame hashes and both manifest hashes matched. Its native Render Queue passed 27 verified keyboard actions and displayed both the audit warning and successful successor. Its process chain and port were verified closed. Exact packaged API/native acceptance and executable provenance are separate gates recorded in the current release manifest. Engineering fixtures do not establish creative taste or client delivery.

### v0.46.2: PNG sequence publication and frontend handoff

The parent integrated the terminal workers into the active development source after reviewing their changes and independently checking 32 publication and 14 frontend regressions. Pictocity 0.2.1 is released. This batch changes PNG-sequence publication, its result links and keyboard behavior; original project libraries remain untouched. Exact package acceptance is separate from these source checks and is bound by the release manifest above.

A logical `name.png` export now publishes `name.frames/`, containing `frame_00001.png` onward and `sequence.json`. The render job's `out` points to `/renders/name.frames/sequence.json`; `output_kind` and `frames` identify the sequence directory, filename pattern and first-frame URL. The manifest records frame count, dimensions, frame rate, requested output duration, individual sizes and SHA256 hashes. Legacy loose `name_00001.png` files are left untouched and are not migrated or deleted. Consumers of the old loose-frame convention must use the job's new sequence location.

FFmpeg writes into an exclusively created sibling staging directory. Before publication the engine requires successful process completion, the exact contiguous frame set, PNG decoding of every frame and the requested output dimensions, including derived sizes. Count validation follows the command's millisecond-rounded output duration and FFmpeg's nearest CFR-frame boundary; it does not introduce an integer/rational timeline. The PNG command now retains its output duration and selected in/out range, which the previous branch dropped when removing the audio map. A manifest and its technical QA are prepared before the directory commit. The PNG job no longer runs single-file video QA against a nonexistent `name.png`.

An exclusive sibling `.frames.lock` covers rendering, validation, publication and cleanup across cooperating threads/processes. An overlapping job targeting the same sequence fails visibly as busy. File/link/junction targets are refused; a destination directory appearing or being replaced during rendering is also refused. Cancellation is checked during rendering, between frame checks and before commit; the cancel route handles the validation phase without an active encoder and serializes with publication. Cancellation after the commit returns `ok: false`.

Rendering failure, validation failure and accepted cancellation preserve the previous destination. Publication renames the previous directory aside, renames the complete stage into place and restores the previous directory if the second rename fails. Successful replacement removes the old tail as part of replacing the whole directory. Ordinary failure/success paths remove job-owned staging and locks. A failed post-commit backup cleanup returns a visible QA warning and retains that backup; a failed rollback reports the retained recovery path instead of deleting it.

The export dialog and Render Queue display distinct Sequence manifest and First frame links, frame count and available technical QA. URL and result text are escaped; invalid output URLs are omitted. Single-file results, mixed output batches, progress and cancellation retain their existing behavior. While export is pending, focus moves to the dialog's Cancel control before Export is disabled, then returns to Export only if the dialog remains open and the user has not moved to another field. Global Enter/Space timeline commands yield to focused buttons, links and menu items. Selecting Render Queue reveals its actual dock; opening a right-hand pane also adds its column to the Editing workspace's inline layout. Fourteen focused frontend tests cover these result, focus, activation and docking regressions.

The first packaged API gate also exposed an intermittent Windows project-save sharing denial during background relinking. Project-file replacement now retries only Windows permission/sharing errors (5/32/33), at most six attempts with 0.5 seconds total backoff, while retaining the previous file. Other filesystem errors fail immediately; persistent denials still raise and retain the temporary candidate for diagnosis. Four tests cover transient and persistent denials, immediate unrelated failures and a real Windows reader released after its first refused replacement. This bounded retry does not add multi-process project ownership, durable transactions or recovery for other JSON stores.

Focused source validation passed 32 tests in `tests/test_png_sequence_publication.py`, with no skips. They exercise the real render route and queue worker in process, injected partial encoder/build/validation/rename failures, rollback and cleanup failures, cancellation before rendering and during validation/publication, destination collisions, thread concurrency and cross-process locking. Existing FFmpeg binaries also exercise successful full/range/fractional-rate/derived-size exports, decoded frame counts, non-frame-aligned output durations, a genuine encoder failure after two written frames, and API cancellation of an active paced encoder. The existing 13 export-safety and 28 resource/relink tests also passed, including real full/incremental video renders; the route guard found all 99 required routes among 115 paths. Those dated tests used their captured interpreter/tools with private temporary/data paths. The older suites used an owned runner that adapts scratch-directory creation to inherit parent ACLs because Python 3.12 mode-0700 temporary directories exclude this sandbox token; their production calls and assertions were unchanged.

Limits: Windows replacement uses two directory renames, so readers can briefly observe an absent path; multi-request readers are not pinned to a generation. This is not crash/power-loss durable, does not fsync publication, and has no automatic restart recovery. A killed process can leave its lock, stage or previous-directory backup; a stale lock is deliberately not stolen. A filesystem that also refuses rollback requires manual recovery from the reported backup. Locks coordinate this implementation's jobs, not arbitrary external frame edits. Source dependencies remain unfrozen during rendering. Full-frame decoding and hashing add export work and in-memory manifest size; large sequences, network filesystems, alternate FFmpeg builds and link/junction behavior require further verification. Native engineering fixtures and source checks establish bounded technical behavior, not creative approval or competitor parity.

### v0.46.1 resource integrity

Exports now have a read-only resource preflight in the API and native dialog. It checks referenced original files, numbered frame continuity, nested sequence references/cycles, graphics images, LUTs, stabilization data and font files. Requested font-family substitutions are visible warnings. Playback proxies do not hide absent originals. Disabled clips, muted tracks and unused bin items do not create source requirements. Workers recheck resources when starting; batch export validates all target sequences before starting its first job. Numbered-frame cache keys include individual source-frame bytes.

Relinking inspects a candidate before changing the project, rejects missing streams and replacements shorter than existing source edits, and warns about dimensions, frame rate and filename changes. An inspection signature rejects stale media state. The commit retains the original media ID, timeline edits, bin/label/notes and other annotations. Old proxy, waveform, stabilization and transcript references are cleared. New previews carry unique generation names, and late background results only update their captured project/source generation. The frontend refreshes media URLs when that generation changes.

The native export dialog has named fields, a keyboard focus trap, an actionable Locate original control (Alt+L), a keyboard-operable Media Browser, resource status and a visible footer inside a bounded window. The desktop editor opens maximized. Media-engine subprocesses explicitly suppress console windows on Windows; a native installed-build check caught the focus-stealing console behavior before the final package. Filename edits preserve focus, and preflight failures disable export.

Focused validation: 28 resource/relink failure-injection tests, the existing 13 export safety tests, 99 required routes (115 present), live API checks and native repair/export verification on isolated projects. Exact installed-build evidence remains in the retained local October 3 resource-review evidence; source checks alone do not certify a packaged build.

Limits: this preflight establishes file availability, not complete decode, glyph coverage, precise font-style matching or visual/audio approval. Source bytes are not frozen for the lifetime of a queued/active render; immutable dependency snapshots and durable bounded jobs remain required release gates. External replacements during ingest/render still need stronger guarantees. PNG publication is addressed by the change above. The preserved real library's six absent original links were not replaced: three are referenced by its active sequence and correctly prevent final export.

### v0.45 export foundation

The desktop launcher supports `--data` so a renamed app can retain an existing project folder without moving files. Windows job objects tie the app and FFmpeg children together; a monitor also exits the extracted app if its onefile bootloader is force-killed.

Full exports now drain FFmpeg progress and stderr concurrently, retain bounded diagnostic output, support cancellation and kill a stalled encoder. Completed single-file output is staged beside the destination and atomically replaces it. A failed export leaves an existing master intact. That release did not include PNG directory transactions; v0.46.2 above provides staged PNG publication with its stated recovery and reader limitations.

Final exports default to a full render. Segment caching remains an opt-in draft path. Cached segments incorporate source bytes, nested sources, LUTs, stabilization data, resolved fonts, graphics images, watermarks and renderer source. Unicode and apostrophe cache paths are covered. Fingerprints are shared inside one export, but fresh jobs read source bytes again. This is a correctness-first choice; repeated render-bar inspections can be expensive on large media and need a measured background fingerprint index. Other rendering modules, FFmpeg version, and source changes during an active job still need stronger dependency and snapshot guarantees.

Post-render analysis has a probe timeout and rejects failed commands. The result records pixel format, declared frame count, frame rate, color tags and output SHA256. Verification failure is visible in the flags rather than looking like an empty successful check. `checked` means these technical checks ran; it is not an artistic verdict, playback review, full decoded-frame audit or delivery approval. Platform limits and the bundled social loudness target are legacy guidance, not live destination requirements.

## Next engineering gates

1. Use integer frame or rational-time editing for fractional rates and drop-frame timecode; compare every decoded frame across full and cached exports at transitions, speed ramps, nested cuts and audio boundaries.
2. Define input, working and output color spaces and test tagged SDR, HDR, log, range and alpha fixtures. A tag alone does not establish correct pixel conversion.
3. Introduce persistent render jobs with input snapshots, bounded subprocesses throughout ingest/analysis/nested renders, restart recovery, progress and cache ownership.
4. Measure long-project ingest, seek latency, export speed, RAM and cancellation on the actual workstation. Test CPU and hardware encoders separately; advertised encoder availability is not an execution result.
5. Reconcile native preview, audio monitoring and export through normal-speed playback and listening. Keep measured checks, user taste and delivery authority separate.

## Reproduce

Use an existing Python environment with the repository requirements and place existing FFmpeg/ffprobe on PATH. Set `TEMP`, `TMP` and `FILMOCITY_ROOT` to an isolated writable test folder. Run `tests/test_export_safety.py`, `tests/test_routes.py`, `tests/test_fuzz.py` with seeds 7 and 17, and `tests/test_catalog.py`. Some older suites use hardcoded ports and historical `/tmp` fixtures; check them before running the entire legacy runner.

Run `tests/test_png_sequence_publication.py` for the PNG publication boundary. It confines its scratch/data paths to `.png-publication-tests` inside this source copy and fails rather than skipping if real FFmpeg is unavailable. It uses inherited directory ACLs for its owned fixtures. No app launch, packaging, network listener or existing project is required. Run `node --test tests/test_png_sequence_ui.cjs tests/test_keyboard_activation.cjs tests/test_panel_visibility.cjs` for the 14 focused frontend regressions.

Run `tests/test_render_queue_lifecycle.py` for bounded queue retirement and event-store failure injection. It requires no encoder, listener or app launch; PNG fixtures use the production renderer with an injected encoder boundary. It retains its owned fixtures and per-case lifecycle evidence in `.render-queue-lifecycle-tests/` instead of removing failed evidence.

`packaging/build.py` freezes the Windows app from existing dependencies and local `bin/` binaries. It does not download them. `FILMOCITY_HEADLESS=1` and `FILMOCITY_PORT` permit isolated packaged testing. Test both health/data identity and process shutdown rather than assuming a successful build is a working desktop release.
